# 现场维护工具

教师登录后进入“现场维护”。无需重新走首次使用向导，不修改考勤计算规则，也不自动开启课次。

## 1. 独立摄像头检测

1. 停止其他窗口的签到或人脸采集，打开“独立摄像头检测”。检测无需学生名单、模型或开放课次。
2. 选择编号 0–9，点击“开始检测 / 重试”。程序只在内存中显示画面，不保存图片、不进行识别、不写签到。
3. 收到连续画面后，人工确认设备、方向、亮度与清晰度；点击“停止检测”，等待设备释放。
4. 如要修改后续使用的设备，显式点击“保存此编号”。测试某编号本身不改变已保存编号；保存不代表现场验收通过。

相机仍使用独立驱动进程，默认读取超时 2 秒、连接等待约 4 秒（另需释放时间）。检测、采集、签到共用跨进程设备锁；驱动实际释放后才允许重试，不删除锁文件。关闭检测窗口或教师端时也等待释放。

## 2. 拔插、断线与重试

- **检测窗口**：报错后等待“设备已释放”，检查 USB、Windows 摄像头权限、其他占用程序，然后点击重试。编号错误时可在释放后更改。
- **学生端**：断线停止识别，按钮在设备释放前禁用；恢复后点击“设备恢复后重试”。重新检查当前课次、名单和模型，不自动恢复旧课次、不重新写已存在签到。
- **人脸采集**：断线后保留已保存样本。设备释放后点击重试，只补采本次剩余张数；也可结束采集。已保存样本应在后续重新训练后使用。
- 无法恢复时，由教师通过“人工点名”登记；检测和重试不会把未成功保存的操作显示为签到成功。

不提供无人值守无限重连。测试中的模拟断线和重试不能替代真实设备拔插、长时间签到和误识别率评测。

## 3. 磁盘空间

- “检查数据磁盘”查看当前数据位置所在卷；“检查其他保存位置”可查看导出或备份位置所在卷，均在后台查询。
- 可用空间低于 **512 MiB** 显示提醒，低于 **100 MiB** 显示不足。
- 采集每张样本、模型训练、Excel 及诊断包导出会检查目标卷，要求至少保留 100 MiB。空间不足时不开始本次保存，也不删除已有文件。
- 完整备份（含自动备份）在目标卷预留约 `2 ×（数据库及 WAL、模型、清单、样本大小）+ 100 MiB`，覆盖临时副本与 ZIP 的保守估算。
- 预检不是配额或容量锁；检查后其他程序仍可能写满磁盘。临时文件原子替换和原有回滚继续处理保存失败。普通名单、签到等数据库写入不被全局空间阈值锁定，底层失败仍显示错误。

## 4. 独立任务时限

教师端训练/删除后重建默认 **180 秒**，考勤 Excel、统计 Excel 及脱敏诊断 ZIP 导出默认 **120 秒**。两项分别允许 **30–3600 的整数秒**，保存在数据库，随完整备份恢复，下次任务生效。

超时请求协作取消，不是强制终止线程或原生 OpenCV 调用。当前原生训练/文件保存返回后，到检查点才停止；期间保留忙状态，不启动冲突任务。新模型及导出文件在最终替换前检查取消。命令行训练和直接调用底层函数由调用方提供任务控制，不读取教师界面时限。普通查询保持 30 秒，备份/校验保持 300 秒。

## 5. 脱敏诊断 ZIP

导出前确认，保存后自行核对，程序不自动发送或上传。包内固定两份文件：

- `diagnostics.json`：应用/Python/OpenCV/SQLite/Tk 版本、平台类别与位数、数据库版本、学生/课次/签到/证据**数量**、磁盘总量与余量、超时设置、白名单事件及异常类型**计数**。
- `说明.txt`：内容边界与分享提醒。

**不复制原始日志**。最多读取四份日志各末尾 256 KiB，只统计固定格式且属于白名单的事件/异常类型，未知行、栈帧、异常值全部丢弃。无日志可导出；日志无权限时仅标记不可用。该概要不是完整故障历史。

不导出姓名、学号、课程、班级、操作署名、备注、路径、用户名、环境变量、密码摘要、数据库、人脸、模型或其哈希。记录数量、容量与生成时间仍可能暴露业务规模，请按内部资料处理。诊断包不是备份，无法用它恢复数据。

## 6. 人脸表单报错与删除中断

告知、授权、撤回或清理提交失败时，错误显示在当前表单底部，填写内容保留，可修改后重试。提交期间关闭或点击取消会请求停止，当前步骤实际结束后恢复按钮；需要关闭表单时再点击取消。通用错误提示归属当前模态窗口，避免主窗口与表单抢占输入。

“删除人脸资料并更新模型”使用持久化暂存清单。进程意外结束后，关闭使用同一目录的其他窗口，再重新启动：审计未提交时恢复原样本与旧模型，已提交时只完成暂存清理。恢复前暂停采集、模型使用、训练及新备份；名单和考勤保留。

如提示旧暂存清单缺失、文件变化或路径异常，程序会保留相关资料。不要自行批量删除 `dataset/.face-delete-*`；应核对原件和备份后由维护者处理。没有清单的旧版暂存目录不会被自动推定为已完成删除。
