# 数据与隐私 / Data and Privacy

> 本文档说明“课堂签到”生成哪些数据、保存在哪里、如何保护、如何删除，以及部署者（学校/教师）需要承担的责任。
>
> **边界声明**：本文是工程说明与合规提示，不构成法律意见。人脸数据属于敏感个人信息，正式部署前请结合所在地区法律、学校制度与专业法律意见评估。

## 1. 数据清单

默认运行数据位于当前 Windows 用户的 `%LOCALAPPDATA%\ClassroomFaceAttendance`，与程序资源分开保存。界面选择的数据位置会持久保存；`--data-dir` 或 `CLASSROOM_DATA_DIR` 可覆盖该位置，命令行优先。原程序目录中检测到旧数据时，启动检查要求显式迁移，原目录保留。

| 路径 | 内容 | 敏感性 | 生成方式 |
| --- | --- | --- | --- |
| `attendance.db` | SQLite 数据库：学生姓名/学号/班级/启停用状态、课次、课次名单快照、签到、原始人脸证据、操作记录、管理密码摘要、摄像头编号、学期设置 | **高**（姓名 + 学号 + 生物特征 + 考勤 + 口令摘要） | 首次启动自动创建；日常使用持续写入 |
| `attendance.db-wal`、`attendance.db-shm` | SQLite WAL 日志与共享内存文件，可能含最近事务内容 | **高** | 运行时由 SQLite 自动生成/回收 |
| `dataset/` | 学生人脸灰度裁剪 JPEG，默认命名 `<学号>.<序号>.jpg` | **高**（生物识别信息） | 管理端采集人脸时生成 |
| `face_model.yml` | LBPH 人脸识别模型，含人脸特征直方图与学号标签 | **高**（生物特征模板） | 管理端训练模型时生成 |
| `model_manifest.json` | 模型版本、训练时间、学生集合、样本数、样本签名、模型 SHA-256 | **中**（含学号集合） | 训练时随模型生成 |
| `logs/classroom.log` 及其轮转文件 | 运行诊断日志；只记录错误类型、文件、行号与函数链，不含异常值、姓名、学号、口令或图像 | **低至中**（仍属运行数据） | 发生错误/事件时写入；1 MB 轮转、保留 3 份旧日志 |
| 完整备份 `.zip`（用户选择位置） | 数据库一致性副本、模型、模型清单、`dataset/` 全部样本、备份信息 JSON | **高** | 管理端“保存完整备份”生成 |
| `classroom-auto-<标识>/auto_*.zip`、`index.json` | 自动完整备份及文件名/大小/哈希归属索引；默认在数据目录 `backups/`，可另选位置 | ZIP **高**，索引中 | 启用后教师端按日生成，按份数受控清理 |
| 考勤导出 `.xlsx` | 学号、姓名、班级、状态、实际到课时间、记录方式、备注、课程、课次时间、原始人脸签到时间 | **高** | 管理端导出生成 |
| `password_reset_<时间戳>.db` | 离线重置管理密码前的数据库副本 | **高** | 运行 `classroom_attendance/maintenance/reset_admin.py` 时生成 |
| `.camera.lock`、`.samples.lock` | 跨进程资源锁文件（内容为占位字节） | 低 | 运行时创建，进程退出后自动释放，文件保留 |
| `resources/initial_data.json` | 空初始化种子（`students`/`attendance` 为空） | 无 | 仓库自带；仅首次初始化读取 |

数据库中主要表的含义：

- `students`：学生档案与启用状态；
- `sessions` / `session_students`：课次与创建时的应到名单快照（含姓名/班级副本、是否仍计入应到）；
- `checkins`：当前有效考勤结果（状态、实际到课时间、记录方式、备注）；
- `face_evidence`：首次人脸签到证据，只允许插入，数据库触发器禁止更新/删除；
- `audit_log`：名单调整、人工更正、课次开启/结束/取消、密码操作等前后值与来源；
- `metadata`：管理密码摘要（PBKDF2）、摄像头编号、学期日期、课程模板、课后核对标记/说明/未认证署名、最近成功备份时间、种子/升级标记等。核对信息随数据库备份、恢复与删除。

> `attendance.db` 中的 `admin_auth` 是**口令摘要**（PBKDF2-HMAC-SHA256 + 随机盐），不是明文密码；但摘要仍可被离线猜测，必须像敏感数据一样保护。

## 2. 数据流向与网络

- 程序是**本地单机应用**：源码中不存在 HTTP/HTTPS、socket、云 SDK 或遥测上报代码。
- 进程间通信仅限本机：GUI 通过本机管道/队列接收相机进程的帧，通过 SQLite 文件共享数据；不会把数据发送到网络。
- 子进程仅用于启动本程序的其他入口（学生端/教师端）与相机驱动，不涉及远程连接。
- 不存在账号登录、云端同步、远程管理或自动更新。

## 3. 敏感个人信息与知情同意

- **人脸图像与人脸模板属于生物识别信息**，通常被法律归类为敏感个人信息；姓名、学号与考勤结果组合后可识别到具体学生。
- 部署者（学校/教师）是数据处理的责任主体。采集前应向学生（未成年人需其监护人）**明确告知**：
  - 采集目的（课堂签到）、采集范围（人脸样本、姓名、学号）、使用方式与访问者；
  - 保存位置与保存期限；
  - 退出的方式与不采集人脸的替代方案（人工签到/请假/教师补签）；
  - 查询、更正与删除的渠道。
- 应取得**明确同意**后再采集；不得强制或欺骗采集，不得采集与考勤无关的人员（如旁听者、访客）。
- 只采集完成签到所需的最少样本（默认每生 20 张）；不采集额外的人脸图像、视频或声纹。
- 学生拒绝人脸采集时，应允许教师通过人工补签、请假/缺勤登记完成考勤，不应影响其正常权益。
- 识别结果只作为辅助记录，保留教师核对与人工更正流程。

## 4. 访问控制与存储安全

- 使用受保护的 Windows 账户；离开电脑时锁屏；不要让无关人员使用同一账户。
- 建议对系统盘/数据盘启用 **BitLocker** 或其他全盘加密；项目目录不要放在公共共享目录或未加密的移动介质。
- 管理密码只保护本机管理界面，**不是操作系统权限隔离**。拥有数据目录读写权限的人可以复制或修改数据库、样本、模型与备份。
- 管理密码使用 PBKDF2-HMAC-SHA256（600,000 次迭代，16 字节随机盐）保存摘要；连续失败会触发递增锁定（5 次失败首次锁 60 秒，之后最长 1 小时），成功登录后失败计数清零。请使用强密码且不要与其他账号复用。
- 学生端只显示脱敏姓名（首字 + `*`）与脱敏学号（仅保留末尾少量字符），完整名单只在教师端显示；但学生端屏幕仍可能被他人看到，课堂使用时应避免多人围观。
- 导出的 Excel、备份 ZIP 与截图都可能包含敏感信息，应存放在受保护位置，不要上传网盘、聊天工具或代码仓库。

## 5. 保留期限与最小化

- “人脸授权”保存告知版本/正文/校验值、授权/撤回历史、同意方式、凭据引用与显式截止日。截止日当天有效、次日零点起停止人脸使用，14 日内到期提醒；没有授权、旧告知或恢复后待复核同样受限。软件不代替真实同意或监护人身份核验，不自动给旧样本补同意。
- 当前版本**不静默按期限删除资料**；部署者在提醒后预览受控清理，复核密码并二次确认。受限或无法归属的样本及受影响模型可删除，保留有效样本、考勤与授权历史；中断需续办，期间人脸与新备份暂停。清理不承诺不可恢复擦除。详见 [人脸生命周期](face-lifecycle.md)。
- 告知和授权/撤回记录保存在数据库的 `face_notices`、`face_authorizations`；清理清单、哈希与状态在 `face_cleanup_jobs`。这些记录和凭据引用也是受保护资料，不随样本期限自动删除。未完成清理可能留下 `.privacy-cleanup-<标识>/` 暂存文件，须从界面续办，不应手工删任务记录绕过暂停。
- 备份恢复后，历史同意不能直接重新生效：逐人复核并新登记，防止较早备份覆盖后续撤回。历史 ZIP、导出、恢复前快照与手工副本不在当前目录的清理范围，需按实际保留策略另行处理。
- 自动备份可保留最近 1–90 份，只有程序索引内且内容一致的旧文件参与清理；未知、变化、占用文件及手动备份需另行管理。
- 自动备份配置与故障重试状态保存在数据库中，含所选本机路径；迁移或换机恢复后暂停并要求重新启用。更换备份位置、删除学生人脸或清空训练数据不会删除旧位置/历史备份内的副本，需按实际保留策略另行清理。自动 ZIP 未加密，同样需要受保护存储。
- 建议原则：仅在完成考勤与必要核对所需的时间内保留；学期或课程结束后导出并加密归档考勤结果，然后删除人脸样本与模型；不再需要时删除数据库与备份。
- 日志按 1 MB 轮转、保留 3 份旧日志；错误日志仍应按运行数据管理。
- 操作记录会保留在数据库中用于核对；界面展示最多 500 条，但数据库中的记录不会自动裁剪。
- 若当地法律/校规对保存期限有更严格要求，以更严格者为准。

## 6. 删除与重置

### 6.1 在管理端删除人脸训练数据

- **删除选中学生人脸**：删除该生样本并重建模型（若其他学生仍有样本），保留名单、课次与考勤时间证据。
- **清空全部训练数据**：删除全部样本与模型，保留名单与考勤时间证据。
- 两项操作都要求重新输入管理密码并二次确认，并写入业务操作记录；历史备份中的人脸副本**不会**被删除，需要单独清理。

### 6.2 忘记管理密码（离线重置）

发行包可在关闭全部窗口后运行 `./ClassroomAttendance.exe --reset-admin` 并在本机对话框中确认；源码也可在仓库根目录执行（自定义数据目录需替换参数）：

```powershell
./.venv/Scripts/python.exe -m classroom_attendance.maintenance.reset_admin --data-dir "$env:LOCALAPPDATA\ClassroomFaceAttendance" --confirm-reset
```

- 脚本要求显式 `--confirm-reset`；不会创建新数据库；若指定目录没有 `attendance.db` 会拒绝执行。
- 执行前会通过 SQLite 备份接口生成 `password_reset_<时间戳>.db`，然后删除管理密码摘要；下次进入教师端可重新设置密码。
- 重置备份同样包含姓名、学号、人脸证据与口令摘要，必须加密保存，或按保留策略删除。

### 6.3 彻底删除全部数据

关闭全部程序后，在“数据与设置”显示的实际数据目录中删除以下内容，并另行清理导出位置：

```text
attendance.db
attendance.db-wal
attendance.db-shm
dataset/
face_model.yml
model_manifest.json
logs/
backups/
password_reset_*.db
restore_status.json
导出的 *.xlsx
```

- 如果只删除数据库而保留模型/样本，启动检查会提示缺少数据库；请确保运行数据一起删除或一起保留。
- 删除前如需保留考勤结果，先导出 Excel 并加密归档；导出文件本身也是敏感数据。
- 删除后重新启动会创建空数据库，需要重新设置管理密码并导入名单。
- **备份、导出与历史副本**需要单独删除；删除主数据库不会影响它们。
- 恢复前原始快照及 ZIP 位于 `backups/pre_restore_*`，同样包含敏感数据。恢复中断时需先让启动检查处理恢复日志；不要只删除日志并保留半套运行文件。完整恢复流程见 [部署与恢复](deployment.md)。
- 已经提交到 Git 的历史或分享到网盘的副本**无法通过本地删除撤回**，请按泄露事件处理（见第 9 节）。

### 6.4 学生查询、更正与删除请求

- 教师端可查询该生的课次名单与考勤记录，并通过人工更正修正结果（保留原因与历史）。
- 人脸样本与模型可通过 6.1 删除；原始人脸证据受数据库触发器保护（禁止单条改删），如需彻底删除应整体删除数据库并评估考勤留存的必要性。
- 删除后无法恢复识别能力，需重新采集与训练。
- 建议学校建立数据主体请求的受理与记录流程。

## 7. 备份保护与恢复

- 完整备份 ZIP 包含：数据库（姓名、学号、签到、证据、审计、密码摘要）、人脸样本、模型与模型清单。
- 备份**默认未加密**。请使用加密压缩包、加密磁盘或受保护的备份系统；不要通过聊天工具、网盘、邮件或公开仓库传输。
- 备份应保存在项目目录之外，并限制访问权限；恢复前先保留当前数据的加密副本。
- 恢复步骤：关闭全部程序 → 将备份中的 `attendance.db`、`face_model.yml`、`model_manifest.json`、`dataset/` 恢复到数据目录 → 重新启动（依赖本项目代码、Haar 级联与已安装的 Python 环境）。
- 若样本与模型签名不一致（例如跨机器复制、手工改动样本），程序会要求重新训练；这是完整性与防误用检查，不是加密保护。
- 备份可被离线读取，因此数据库中的管理密码摘要可能被离线猜测；请使用强密码并妥善保护备份。

## 8. 日志策略

- 日志位置：`logs/classroom.log`；按 1 MB 轮转，保留 3 份旧日志。
- 记录内容：事件名、错误类型、调用链中的文件名/行号/函数名；**不写入**异常值、源代码、局部变量、姓名、学号、口令或图像。
- 日志仍可能包含本机文件布局信息，应按运行数据管理；删除全部数据时一并删除 `logs/`。
- 需要排查问题时，可在终端运行 `python app_entry.py` 观察输出；不要公开粘贴未脱敏的完整日志或截图。

## 9. 泄露事件处置（建议）

如果发现真实数据被误提交到 Git、上传网盘/群聊、备份丢失或设备失窃：

1. 立即停止使用并隔离相关设备/仓库；
2. 尽可能删除/撤回公开数据，但**不要假设可以完全撤回**（Git 历史、fork、缓存、下载副本可能仍存在）；
3. 重置管理密码（需要持有数据库文件权限时使用 `classroom_attendance/maintenance/reset_admin.py`）；
4. 评估是否需要删除/轮换数据、通知受影响的学生/监护人/学校；
5. 记录事件经过、范围、处置与通知情况；
6. 检查是否存在其他泄露渠道（备份、导出表格、聊天记录、截图）。

## 10. 公开仓库与本项目的责任边界

- 本仓库**不包含**任何真实人脸、姓名、学号、数据库、模型、备份、日志或导出表格；测试使用临时数据库、合成图片与模拟相机。
- 禁止在 Issue、PR、评论、附件或 Release 中上传真实数据；维护者会删除并提醒提交者。
- 开源许可（MIT）不改变部署者的个人信息保护义务；软件作者不对部署方的采集、告知同意、保留与删除行为负责。
- 部署者应自行评估当地法律、学校制度、未成年人保护与伦理要求，并保留必要的告知同意记录。

- [ ] 已向学生/监护人告知采集目的、范围、期限、访问者与退出方式，并取得同意。
- [ ] 已提供不采集人脸的替代考勤方式。
- [ ] 已启用磁盘加密、受保护账户与锁屏策略。
- [ ] 已限制数据目录与备份目录的访问权限，备份已加密并离线保存。
- [ ] 已制定保留期限与删除流程，明确谁负责执行。
- [ ] 已告知教师：识别结果仅供辅助，必须人工核对并保留补签渠道。
- [ ] 已确认管理密码强度，且未与其他账号复用。
- [ ] 已确认仓库、Issue、Release 中不包含真实数据。
- [ ] 已了解识别准确率与防代刷能力不作承诺。
