## 首次使用

新用户从主入口或教师端进入首次使用向导，按以下顺序完成：

1. **数据位置**：确认并保存默认目录，或选择已有/新的数据目录；已有 ZIP 备份可先恢复。选择其他目录后会重新打开程序，使所有路径保持一致。通过 `--data-dir` 或环境变量指定的位置直接视为已选定。
2. **管理密码**：自行设置 8–128 个字符的密码，没有默认密码。续办时使用已设置密码登录，不会再次要求设置。
3. **摄像头测试**：选择编号 0–9，点击“开始测试 / 重试”，确认连续画面后点击“画面正常，继续”。只在内存显示，不保存照片、不识别、不签到；设备占用或断开可重试，也可明确跳过使用人工点名。继续或关闭前会等待设备释放。
4. **学生名单**：下载 CSV 模板，或读取 CSV/XLSX 预览新增/更新与启用状态；确认前不写入。已有学号更新姓名和班级，原停用状态保留。预览后的相关档案发生变化需重新读取，整批名单与进度同时提交。也可沿用已有启用名单或明确稍后导入。
5. **完成检查**：查看实际数据位置、密码、摄像头及名单状态，再选择教师首页、采集与训练或人工开课。跳过步骤会明确显示；没有启用学生时仍需先维护名单，刷脸签到前需先采集并更新模型。

点击“稍后继续”或关闭窗口后，已确认步骤随数据库保存；下次登录继续未完成步骤。已完成向导和已有密码/业务数据的旧用户不自动重复引导；在“数据与设置 → 首次使用向导 / 重新检查”打开设置复核时保持原进度，直接关闭不会要求下次登录重新走向导。需要重做时，点击复核页的“重新开始向导”并确认，才将摄像头和名单步骤重置为未完成；密码、名单和考勤保留。向导进度随完整备份恢复，未完成进度换目录后重新测试摄像头。学生入口保持签到功能，不展示管理向导。

- 首次启动会自动创建空数据库；初始化种子文件 `initial_data.json` 为空模板，不会导入示例学生。
- 学生端在老师开启课次后才会允许开始识别；模型尚未训练时，学生端会提示联系老师。
- 依赖分工：`requirements.txt` 是用户统一安装入口，引用 `requirements-lock.txt` 中的固定版本；CI 直接使用同一锁文件。`requirements-build.txt` 仅用于构建 EXE，日常运行无需安装。升级依赖时集中修改锁文件并验证。
- 不要同时安装多个共用 `cv2` 命名空间的 OpenCV 发行包；本项目需要 `opencv-contrib-python`（含 face 模块）。

## 使用流程

### 教师端（6 步）

1. **维护名单**：在“学生与人脸”新增学生（学号 1–24 位数字，保留前导零；姓名、班级可选填班级默认“未分班”），或导入首行含“学号、姓名”的 `.xlsx` / `.csv`；整批导入失败时不会写入部分数据。
2. **采集人脸**：先在“人脸授权”页按实际知情同意情况登记有效授权；选择已保存且启用的学生，点击“采集人脸”，保持画面中一人并按提示缓慢转头、改变表情；默认采集 20 张，提前结束会保留已保存样本。
3. **更新模型**：点击“更新识别模型”。新模型只纳入启用学生；页面会提示已覆盖与尚未训练的学生。样本变动后需要重新训练。
4. **创建课次**：在“课次管理”填写课程、班级、开放签到、正式上课、迟到起点和关闭签到；开放至关闭不超过 24 小时，创建时保存应到名单快照。
5. **开启签到**：选中课次后点击“开启签到”。需要可用模型，且当前时间必须处于课次时段内；同一时刻只允许一个开放课次。部分应到学生尚无模型时会提示老师确认，这些学生需要人工补签。
6. **结束与核对**：签到中的课次可手动结束或到时自动结束；在“考勤记录”筛选、核对、人工更正并导出 Excel。未开启的课次超时不算缺勤，未上课请填写原因并取消课次。

### 课次的四个时间点

时间须满足 **开放签到 ≤ 正式上课 ≤ 迟到起点 ≤ 关闭签到**，正式上课须早于关闭，开放至关闭最多 24 小时。单次课次填写完整本地日期与时间；例如开放 07:40、正式上课 08:00、迟到起点 08:05、关闭 09:30，07:40 起可签到，08:05 这一秒起算迟到，09:30 不再接受签到。迟到起点等于正式上课时，从上课这一秒起计迟到；等于关闭时，所有有效签到均不记迟到。

到开放时间不会自动开课，仍需教师手动开启；关闭时间到达后停止接受签到并在查询时结束。教师也可提前手动结束。人工点名沿用同一开放时段与唯一开放课次规则，人工更正仍采用教师明确登记的状态。

单次创建、周期预览、学生端、课次详情和 Excel 明细显示四个时间点；统计、首页及查询范围均按**正式上课日期**归属，前日开放或次日关闭不改变归属日期。周期排课可勾选“开放签到在前日”“迟到起点在次日”“关闭签到在次日”，日期范围和星期均指正式上课日。时段冲突按整个开放至关闭区间判断。

首次打开旧库时事务升级到 schema 5。schema 3 及更早课次的开放与正式上课均沿用原签到开始时间，原迟到起点、关闭时间、考勤、证据及有效核对标记保留；旧模板按原宽限精确换算。新增告知、授权/撤回及清理记录，不为旧资料推定同意。schema 3/4 备份可先只读校验和恢复，打开后再升级；所有恢复后的人脸授权需逐人复核，人工点名不受影响。

升级前请保存完整备份并关闭所有旧窗口；升级后的数据目录请使用新版程序，回退旧版时应恢复升级前备份。

### 今日课堂与课后核对

教师登录后默认显示“今日课堂”：

- 今日课次与已到/应到按正式上课日期统计，待开启和已取消课次不计入考勤人数。前日已开放或跨日仍开放的课次单独显示在“当前课次”和“当前未签到”，不会改写归属日期。
- 选择课次可直接进入课次管理、人工点名或查看考勤；选中未签到学生后进入考勤，会定位到本人。历史待核对课次使用“选定课次日期”精确定位，导出保留该课次条件；切换回当天、当周等范围可恢复普通查询。
- “待核对课次”统计所有未核对或变更后待复核的已结束课次，列表显示其中最近 30 个。选中课次点击“课后核对”，先查看状态、实际到课时间、首次人脸时间和备注，再到“确认核对”勾选确认，可选填说明和未认证署名。
- 确认只记录核对进度，不更改缺勤、请假、时间未知或其他考勤结果。确认时再次核对快照；若记录或名单变化，需要刷新明细。之后通过程序更正或调整名单，该课次会重新进入待核对；重复相同更正或核对不会重复写事件。
- 首页显示启用学生的人脸模型覆盖；模型未就绪时提示使用人工点名。最近成功备份时间由本版完整备份成功后记录，失败不更新；时间来自数据库记录，不代表原备份文件仍存在，也不替代恢复校验。

核对标记、说明与署名随数据库备份恢复；这是本机管理记录，署名没有独立账号认证，不构成防篡改证据。

### 统计报表

教师端打开“统计报表”，首次自动使用已保存的当前学期。也可填写包含首尾的日期范围（`YYYY-MM-DD`），选择课程与学生的历史班级，点击“生成报表”。修改筛选后需重新生成，方可导出；空范围不会扩展为全部数据。“使用当前学期”会重新读取学期设置。

- **学生学期汇总**：每个学号一行，显示应到、已签到、迟到、请假、缺勤、已到、到课时间未确认、出勤率和准时率。姓名及班级显示该学生在选定范围内最近一次名单快照；停用、改名、转班不会改写历史明细。
- **课程汇总**：按课程名称与课次班级合并，统计已结束课次数与人次；同名同班的课程合并。同一天不同课次分别统计。
- **学生 × 课次矩阵**：每列含独立课次编号、课程、课次班级及开始时间；“—”表示该生不在该次应到名单，而非缺勤。双击格子或选中学生按回车可看当前快照明细。
- **导出 Excel**：一次导出学生汇总、课程汇总、矩阵、考勤明细及统计口径五张工作表，沿用页面最近生成的同一快照、筛选与生成时间。学号和用户文字按文本保存，百分比为数值；中途失败或取消不覆盖已有文件。

**出勤率 =（已签到人次 + 迟到人次）÷ 应到人次；准时率 = 已签到人次 ÷ 应到人次。** 迟到计出勤，请假保留在应到分母内；例如已签到 2、迟到 1、请假 1、缺勤 2，共应到 6 人次，出勤率为 50.00%。应到为 0 显示“—”，合计按总人次相除，不平均各行百分比。

只统计已结束课次（包括已到关闭时间的签到中课次），按正式上课日期归属；进行中、待开启、已取消课次和已移出名单者不纳入。应到以每个课次保存的名单快照为准，班级筛选采用学生的课次班级快照。人工更正后采用当前有效状态，时间未确认仍按登记状态计数。更正、核对或调整名单后请重新生成报表；“统计口径”可查看完整说明。统计报表不代表已完成真实课堂识别评测。

### 课程模板与周期课次

在“课次管理”左侧点击“课程模板 / 周期课次”（小屏可向下滚动），可一次准备整段教学安排：

1. 在“课程与周期”填写模板名、课程、班级与四个时间点，选择每周上课日及周间隔（1–8 周），填写包含首尾的正式上课日期范围（最多 366 天）。隔周的第 1 周从首日期所在的周一开始；跨日使用前日开放、次日迟到及次日关闭选项，开放至关闭仍不超过 24 小时。
2. 在“选课名单”选择按当前启用班级取名单，或用 Ctrl / Shift 选择固定选课名单；跨班选课时班级选择“全部学生”。固定成员停用或转班后须明确重选，不会悄悄漏掉。
3. 点击“预览课次”，核对每个日期、签到时间、名单快照和冲突。“名单快照”展示完整本次应到人员；可跳过所选停课日期或全部冲突日期，再重新预览。
4. 同一单机上任何未取消课次的时段重叠都视为冲突，相邻时段不冲突；冲突未处理时不能生成。确认时重新核对日期、名单和时段占用，整批成功或整批回滚，重复点击不会生成重复课次。
5. 确认生成后全部为“待开启”，仍由老师在时段内逐次开启。需要临时停课可使用原有的取消课次入口；补课可单独创建。

“保存模板”只保存课程、四个时间点与跨日选项、星期、周间隔与名单方式，不保存本次日期范围和跳过日期。更新模板不修改已生成课次，每次生成分别保存当前姓名及班级快照。模板随数据库备份与恢复，新模板使用版本 2，兼容读取版本 1。

### 人工点名与故障兜底

不采集人脸、模型未训练、识别失败或相机不可用时，教师可以直接完成考勤：

1. 在“课次管理”选择课次，点击“人工点名”。待开启课次先到“登记与预览”填写原因，再点击“开启人工点名”；无需模型或摄像头，仍遵守签到时段、应到名单和唯一开放课次规则。
2. 在“选择学生”按学号、姓名或班级搜索，用 Ctrl / Shift 多选；“全选当前结果”只选择当前可见结果，切换筛选会清空选择。
3. 切到“登记与预览”，选择已签到、迟到、请假或缺勤，填写原因。默认保留各自原到课时间；新补签必须填写统一实际到课时间，或明确选择“时间未确认”。程序不会自动填入当前时间。
4. 点击“预览登记”，逐人核对状态与时间，再确认登记。提交整批成功或整批回滚；若所选人员在预览后发生签到、更正、名单移出或课次状态变化，需刷新并重新预览。
5. 返回课次页结束签到，再核对与导出。也可从“考勤记录”选中具体课次或记录后进入人工点名。

已有备注、名单快照与首次人脸证据保留，每人均写入原有更正历史，并保存批量操作记录。署名是选填文本，未经账号认证。人工开课后，学生端在模型可用时仍可刷脸；刷脸不会覆盖已登记的人工结果。学生端会提示识别失败的同学联系老师人工登记。

### 学生端（5 步）

1. 打开学生端，等待老师开启课次。
2. 点击“开始识别”，相机预览显示在页面内。
3. 每次一人正对摄像头，保持清晰稳定；通过连续身份确认后显示本人签到结果与时间。
4. 相机可持续为多位学生签到，不需要每位学生重新点击；重复签到不会覆盖第一次记录。
5. 课次结束时相机会自动停止，也可以手动停止。

学生端不展示全班名单；结果中的姓名只显示首字加星号，学号只显示末尾少量字符。请假、缺勤等人工结果不会被后续重复刷脸直接覆盖。

### 界面操作

- 主窗口和常用弹窗会根据桌面可用区域设置初始尺寸；教师端通常可缩小到 940×600，入口页与学生端可缩小到 900×560。可用区域更小时会继续降低最小尺寸。
- 学生信息、创建课次、数据与设置、学生端课次信息及人工更正表单支持滚动；鼠标放在面板内滚动，或用 Tab 切换到下方字段。长表格可通过底部滚动条查看右侧列。
- 课次页点击“应到名单”调整成员，点击“课次详情”查看课次状态与取消原因。“创建课次”固定在表单底部，人工更正的“返回”和“保存更正”固定在弹窗底部。
- 训练、备份、导出运行时显示活动进度条与已用秒数。点击“取消任务”后会等待当前步骤结束，结束后才恢复操作；主动取消不再弹出失败提示。活动进度条不表示完成百分比。
- 底部操作提示支持换行；单击提示文字可查看完整内容，也可用 Tab 聚焦后按回车或空格查看。空名单、空课次和空考勤页会提示下一步操作。

## 考勤规则（摘要）

- **签到时段**：只有在开放签到时间至关闭签到时间之间（关闭时刻不含）且课次状态为“签到中”时才接受人脸签到，正式上课前也可签到。
- **迟到**：从独立设置的迟到起点这一秒起计迟到；迟到起点等于关闭时，关闭前均不记迟到。旧接口和旧模板仍兼容“原开始时间 + 宽限，最多到关闭”的计算。
- **缺勤**：已结束课次的未签到应到学生计缺勤；签到中的未签到显示“未签到”，不计为缺勤；待开启、已取消、已移出名单的人员不参与统计。
- **取消与结束**：只有待开启课次可取消（需填写原因），只有签到中的课次可结束；已结束课次不能取消，未开启课次超时也不产生缺勤。
- **唯一记录**：同一学生在同一课次最多一条有效签到记录；同一天不同课次可分别签到。数据库唯一约束与事务负责去重。
- **更正**：只有签到中或已结束课次可以人工更正；必须填写 1–300 字原因。实际到课时间默认保留，补签时须填写时间或明确勾选“时间未确认”。相同更正重复提交不会重复写事件。
- **证据**：首次人脸签到证据独立保存，更正状态或到课时间不会覆盖原始证据。
- **名单快照与调整**：课次创建时保存成员姓名与班级；后续档案修改不会自动改变该课次名单。待开启课次可按当前启用班级刷新新增/移出；签到中与已结束课次可按学号增补或移出，需填写原因并先预览确认；移出后原有签到与证据仍保留。
- **操作署名**：教师署名是选填的管理操作署名，未经独立账号认证；未署名时记录为管理入口操作，不能据此认定真实身份。

详细规则见 [docs/design/business-rules.md](design/business-rules.md)。

## 相机与模型

- 人脸检测使用 OpenCV Haar 级联，身份识别使用 LBPH；输入为灰度图，训练前缩放到 `160×160` 并做直方图均衡。
- 默认摄像头编号为 0，可在管理端“数据与设置”修改（0–9）；采集与签到共用跨进程相机锁，两个窗口不能同时占用相机。
- 识别距离阈值为 **小于 60**；同一身份需要连续 **至少 8 次**匹配且持续 **至少 1 秒**才算确认。
- 识别线程约每 **0.75 秒**复核课次、启用名单与模型版本；检测到课次结束或模型失效会停止。
- 采集/识别有画质门槛：人脸区域至少 100 像素，亮度约 45–215，清晰度（Laplacian 方差）不低于 45。
- 新模型使用文件名和样本内容 SHA-256 生成持久签名，文件时间变化不会导致失效；运行中按文件元数据缓存哈希，训练和恢复强制重新读取。兼容旧 v2 模型，新备份会将有效的 v2 模型清单升级为内容签名 v3。样本内容变化、模型损坏或版本不符时仍需重新训练；停用学生不影响其他学生。
- **没有经过验证的活体检测**：二维摄像头 + LBPH 无法可靠区分真人、照片或视频，**不得宣传“防代刷”**。连续确认与画质检查不等于活体检测。
- 识别准确率受光线、角度、摄像头质量、样本数量影响，**尚未经过充分的现场验证**；目前仅建议在测试环境评估效果，并保留人工核对与补签渠道；测试不代表可以直接投入正式考勤。

## 数据与隐私

### 每日自动备份

在教师端“数据与设置 → 自动备份”勾选启用，设置每日时间（`HH:MM`）、保留份数（1–90，默认 7）及保存位置，然后保存。默认关闭；启用后仅在教师端打开期间检查，错过时间补做当天一次，不补生成过去日期的备份。电脑或教师端关闭期间不执行。

“立即备份 / 重试”使用已保存设置，允许当天再次生成；执行中可取消。采集或训练占用样本锁时 1 分钟后重试，其他失败或取消未完成的备份后 10 分钟再检查，避免立即重启任务。失败与清理异常在设置页保留，首页显示“自动备份需处理”。

文件放在所选位置下独立的 `classroom-auto-<数据目录标识>/`，`index.json` 记录程序生成文件的大小与 SHA-256。只在新完整备份成功后清理旧自动备份；未知文件、手动备份、恢复前快照和内容变化的文件保留。索引损坏时停止自动写入与清理；可检查原目录或更换保存位置。切换位置不会清理原位置。

换机恢复或迁移数据目录后自动备份暂停，请确认新位置并重新启用。默认目录与数据库位于同一磁盘，不能防止磁盘损坏；需要保护并另存到合适的备份介质。ZIP 未加密，自动保留份数也不等于学生数据保存期限；删除人脸资料后，应另行清理历史备份中的副本。

### 运行数据文件

| 路径（相对于运行数据目录） | 内容 |
| --- | --- |
| `attendance.db`（含 `-wal`/`-shm`） | 学生姓名、学号、班级、课次与名单快照、签到、原始人脸证据、操作记录、管理密码摘要、学期与摄像头设置 |
| `dataset/` | 人脸样本 JPEG 裁剪图 |

| `logs/classroom.log`（及轮转文件） | 运行诊断日志，已脱敏，不含姓名、学号、口令、异常值或图像 |
| 用户选择的 `backups/*.zip` 或备份位置 | 数据库、模型、样本与备份信息 |
| 用户导出的 `.xlsx` | 姓名、学号、班级、考勤状态、时间与备注 |
| `.camera.lock`、`.samples.lock` | 运行期资源锁文件，程序退出后失效 |

### 隐私要点

- **本地存储、无网络**：代码中没有任何网络请求、上传、遥测或云同步；数据只保存在运行本机。
- **敏感个人信息**：人脸图像与人脸模板属于生物识别信息，姓名 + 学号 + 考勤结果可识别到具体学生。部署者（学校/教师）应在采集前告知用途、范围、保存期限，并取得学生（未成年人需监护人）的明确同意；在适用法律要求时履行个人信息保护义务。
- **访问控制**：管理密码只保护本机管理界面，**不是操作系统权限隔离**。能访问项目文件或数据库的人仍可修改程序或数据；请使用受保护的 Windows 账户，并考虑启用 BitLocker 等磁盘加密。
- **备份保护**：完整备份 ZIP 包含数据库、人脸样本、模型与管理密码摘要，且默认未加密。请保存到受保护位置并加密（如加密压缩包/加密磁盘），不要上传网盘、聊天工具或代码仓库。
- **日志**：日志只保留错误类型和文件、行号、函数调用链，去掉异常值、源代码与局部变量；日志仍属运行数据，删除数据时一并清理。
- **导出表格**：导出的 Excel 含姓名、学号与考勤信息，请按敏感文件管理。

### 删除与重置

- **授权、到期与撤回后清理**：在“人脸授权”查看告知、登记授权/撤回与期限；受限资料可预览受控清理，需密码与再次确认，失败/中断需续办。只处理当前目录的人脸样本及受影响模型，考勤和授权历史保留；历史备份需单独处理。详见 [人脸授权与清理](face-lifecycle.md)。
- **删除某个学生的人脸资料**：在管理端“数据与设置”选择“删除选中学生人脸”，需复核管理密码并二次确认；会删除样本并重建模型，**保留**名单与考勤时间证据。
- **清空全部训练数据**：在“数据与设置”选择“清空全部训练数据”，同样需复核管理密码；之后须重新采集并训练才能刷脸。
- **忘记管理密码**：发行包可在关闭全部窗口后运行 `./ClassroomAttendance.exe --reset-admin`，在本机对话框中确认；源码也可在仓库根目录执行（自定义目录请替换参数）：

  ```powershell
  ./.venv/Scripts/python.exe reset_admin.py --data-dir "$env:LOCALAPPDATA\ClassroomFaceAttendance" --confirm-reset
  ```

  脚本会先把当前数据库备份为 `password_reset_<时间戳>.db`，再删除管理密码摘要；下次进入教师端需重新设置密码。
  备份文件含敏感数据，请妥善加密保存或按保留策略删除。
- **彻底删除全部数据**：关闭全部程序，打开“数据与设置”显示的运行数据目录，删除 `attendance.db`（含 `-wal`、`-shm`）、`dataset/`、`face_model.yml`、`model_manifest.json`、`logs/`、`backups/`（包括恢复前快照）以及导出的 `.xlsx` 与重置备份。
  注意：如果删除了数据库但保留了模型或样本，启动检查会提示缺少数据库；请把运行数据一起删除或一起保留。需要保留考勤结果时，先导出并加密保存。
- **原始人脸证据**：数据库触发器禁止单条更新或删除首次人脸证据；如需行使删除权，应通过管理端删除人脸样本并评估是否整体删除数据库。

更多说明见 [docs/data-and-privacy.md](data-and-privacy.md)。本文档不构成法律意见；正式部署前请咨询学校或专业法律人员。

## 已知限制

- **无活体检测**，不能阻止照片/视频/屏幕翻拍代刷；识别结果只能作为辅助记录。
- **准确率未充分验证**：LBPH 对光线、角度、遮挡和摄像头差异敏感；未做大规模、多人、长时间现场验证。
- **单机单摄像头**：同一时刻只允许一个开放课次；没有多机位、多教室同步或网络集中管理。
- **无账号体系**：教师端只有一个共享管理密码，没有多教师账号、角色权限或独立审计身份；教师署名是选填文本，不构成实名认证。
- **本地文件可信边界**：管理密码不防御拥有本机文件权限的人；数据库、样本、模型、备份默认未加密；操作记录是本地管理记录，不是司法级防篡改证据。
- **平台限定**：仅在 Windows 10/11 + Python 3.11 验证；Linux/macOS、其他 Python 版本未验证。
- **发行包处于预览阶段**：已提供 PyInstaller 解压包构建与自检；干净 Windows 电脑、目标摄像头与换机现场验收仍待完成。
- **后台任务超时**：教师端训练/删除后重建默认 180 秒，Excel/诊断包导出默认 120 秒；“现场维护”可分别设置 30–3600 秒，下次任务生效。超时为协作取消，原生训练和文件保存需返回检查点后结束；普通查询默认 30 秒，备份及备份校验为 300 秒。实际恢复使用独立窗口，替换期间不能主动取消，异常或进程中断由恢复日志处理。
- **窗口尺寸**：已加入小屏布局与滚动表单；极低分辨率或较高系统缩放下，部分内容仍需通过面板与表格滚动条浏览。
- **到时自动关闭**：由运行中的程序通过查询触发（约每 1–3 秒刷新）；所有窗口都关闭时不会在后台关闭课次，但下次查询会补做关闭。
- **无云端能力**：不支持移动端、Web、在线选课、消息推送或跨设备同步。
- **未提供示例截图/演示 GIF**：仓库只预留 `docs/images/`；制作演示素材必须使用虚构数据并对人脸打码。

## FAQ

**Q：提示“摄像头正在使用”或相机打不开？**
A：同一台电脑上采集与签到共用相机锁。先停止学生端识别，再进行采集/训练；关闭其他占用摄像头的程序；确认摄像头编号（0–9）；USB 摄像头可尝试重新插拔，必要时重启程序。

**Q：提示“请先训练模型”“样本已更新”或“模型信息损坏”？**
A：完成或补采样本后点击“更新识别模型”。手动增删改样本、混用不同批次模型与样本、模型损坏时需要重新训练；新版备份正常恢复且内容校验通过时可继续使用模型。停用学生不需要重新训练。

**Q：忘记管理密码怎么办？**
A：关闭全部程序，发行包运行 `./ClassroomAttendance.exe --reset-admin` 并在本机对话框中确认；源码使用 `reset_admin.py --data-dir <实际数据目录> --confirm-reset`。操作先备份数据库，再清除密码摘要；下次进入管理端重新设置密码。

**Q：学生停用后有什么影响？**
A：停用只禁止后续人脸签到，并使该生默认不进入新课次名单；既有课次的应到名单不变。停用不会让其他学生的模型失效；重新启用但尚无模型覆盖的学生会提示需要训练或人工补签。

**Q：如何清空所有数据或重新开始？**
A：局部删除用管理端“删除选中学生人脸”/“清空全部训练数据”；彻底清空按“删除与重置”删除数据库、样本、模型、日志、备份和导出文件。删除后重新启动会得到空项目，重新设置密码并导入名单。

**Q：画面里有多个人会怎样？**
A：识别要求画面中恰好一张人脸；多人、无人、身份变化或画质不足时不会签到，只提示调整。请一次一人正对摄像头。

**Q：为什么学生端看不到课次？**
A：需要老师创建课次并在时段内点击“开启签到”，且同一时刻只能有一个开放课次；人脸识别需要可用模型。老师也可在“人工点名”填写原因后无模型开课并人工登记。学生端会每 2 秒刷新当前课次。

**Q：能不能把程序放到另一台电脑？**
A：可以。复制整个发行目录，在新机器通过恢复窗口导入新版备份；内容校验通过的 v3 模型可继续使用，仍应重新测试新摄像头效果。旧格式或未就绪模型须重新训练。备份与数据库含敏感数据，请保护迁移介质。

**Q：识别结果可以直接作为考勤依据吗？**
A：不建议。当前实现没有活体检测，准确率也未经充分验证；请保留教师核对、人工更正与补签流程。
