# Windows 发行与数据恢复

> 本页面向自行构建和验证的开发者。当前项目处于开发预览阶段，数据仍在整理，真实课堂验证尚未完成；下文的构建和恢复步骤不代表已具备正式部署条件。首次体验可先看 [项目首页](../README.md#怎么运行)。

本版本提供 Windows x64 解压发行包。使用者无需安装 Python；构建发行包的开发者需要 Python 3.11。下载与安装构建依赖需要网络，发行包日常运行不需要网络。

源码根目录保持单一 `app_entry.py` 入口；可选的旧 BAT 集中在 `tools/launchers/`，不加入新构建的发行包。本机源码运行使用 `tools/create_shortcuts.ps1` 生成的三个桌面快捷方式；发行包直接双击 `ClassroomAttendance.exe`，保留完整的 `_internal/` 目录。

## 使用发行包

第 8 轮预览包细化课次时间：分别填写开放签到、正式上课、迟到起点、关闭签到。开放 ≤ 上课 ≤ 迟到 ≤ 关闭，上课早于关闭，整个窗口最多 24 小时；到开放时间仍需教师手动开启。周期排课可选前日开放、次日迟到与次日关闭，冲突覆盖整个窗口。首页、查询和报表按正式上课日期归属，学生端及 Excel 明细显示四个时间点。

本轮数据库升级到 schema 5。升级前请保存完整备份并关闭所有旧窗口；四时间、课次、考勤证据、密码和模板保留，新增告知、授权/撤回及清理记录，不为旧样本推定同意。schema 3/4 备份先只读校验和恢复，打开后再升级。恢复后的授权一律待复核，逐人核验后才可刷脸；人工点名不受影响。升级后的数据目录只用新版；需要回退旧版时恢复升级前备份。

第 7 轮预览包新增首次使用向导。新用户从主入口或教师端依次确认数据位置、设置管理密码、测试摄像头、预览并导入名单，最后检查完成情况。摄像头可跳过改用人工点名，名单可明确稍后导入；关闭后登录续办。已完成向导或已有密码/业务数据的旧用户沿用原入口，可在“数据与设置”主动重开。测试不保存相机图片、不识别或签到；关闭或继续前等待设备释放。进度与名单随数据库备份恢复，无需迁移数据库结构。

第 6 轮预览包新增“统计报表”：学生学期汇总、课程汇总及学生 × 课次矩阵，可按日期、课程和历史班级筛选。点击“生成报表”后导出包含明细和口径的五表 Excel。只计已结束课次；出勤率为（已签到 + 迟到）/ 应到，请假计入分母，零应到显示“—”。数据更正后需重新生成。已有用户无需迁移数据库结构。

第 4 轮预览包新增教师“今日课堂”首页与课后核对。登录后可查看今日课次、当前未签到、模型覆盖、最近备份时间和待核对列表，直接进入管理、人工点名或精确课次考勤。已结束课次核对后勾选“确认核对完成”；之后通过程序修改考勤或名单会重新提示复核。核对标记随数据库备份恢复，无需变更数据库结构。

第 3 轮预览包新增课程模板与周期课次。在课次页左侧点击“课程模板 / 周期课次”，填写星期、周间隔、日期范围和名单方式后预览。可跳过停课日与冲突日；核对名单快照后批量生成待开启课次，再逐次开课。模板随完整备份恢复，已有数据库结构无需迁移。

第 2 轮预览包新增“人工点名”：在“课次管理”选择课次，点击“人工点名”；待开启课次先到“登记与预览”填写原因，再点击“开启人工点名”，无需模型或摄像头。选择学生后填写状态、时间处理方式和原因，点击“预览登记”，核对逐人结果再确认；底部按钮固定可见，登记表单可滚动。也可从考勤记录选定课次或记录后进入。结束时返回课次页点击“结束签到”。原有用户无需迁移数据库结构。

1. 将整个 ZIP 解压到普通本地目录。保留 `ClassroomAttendance.exe` 与 `_internal/`，不要只复制 EXE。
2. 双击 `ClassroomAttendance.exe`，首次启动确认运行数据位置，也可选择已有数据目录或进入备份恢复。
3. 新用户按首次使用向导完成设置，再按“学生与人脸 → 课次管理 → 考勤记录 → 统计报表”的流程使用。
4. 直接入口可通过快捷方式参数指定：`--role admin`、`--role student`、`--role restore`。
5. 校验或恢复备份可从数据位置选择页或教师端“数据与设置”进入；也可运行 `./ClassroomAttendance.exe --role restore`。忘记密码时关闭所有签到窗口，再运行 `./ClassroomAttendance.exe --reset-admin`，在本机确认对话框中复核并重置，旧库会先备份。

默认运行数据在当前用户的 `%LOCALAPPDATA%\ClassroomFaceAttendance`；程序资源位于发行目录。更新时关闭所有窗口，替换整个程序目录，保留用户数据目录。界面选择的位置保存到默认用户目录内的 `data_location.json`，下次双击仍使用该位置。保留 `CLASSROOM_DATA_DIR` 环境变量，并支持 `--data-dir` 指定数据目录；命令行参数优先。目录切换会重新启动程序，避免同一窗口混用不同目录。

源码安装使用 `.venv` 和 `app_entry.py`，或使用 `tools/create_shortcuts.ps1` 生成的桌面快捷方式；例如在项目根目录运行 `./.venv/Scripts/python.exe app_entry.py --role admin`。启动时若发现程序目录内有旧版数据库、样本或模型，不会静默创建一个全新的空库；需明确选择迁移。迁移只复制数据，保留原目录。当前使用数据库 schema 5，兼容恢复 schema 3/4；未知或更高版本拒绝恢复，新版启动也拒绝迁移高版本数据库。

## 备份、校验与恢复

第 5 轮支持每日自动备份。在“数据与设置 → 自动备份”启用，设置 `HH:MM`、保留数量（1–90）与保存位置并保存。默认关闭；教师端运行期间每约 15 秒检查，错过时间仅补当天一次，多个教师窗口使用跨进程锁去重。窗口关闭时不在后台运行。采集/训练占用资源时延后 1 分钟，其他故障 10 分钟后重试，也可点击“立即备份 / 重试”或取消。关闭正在备份的教师端会先请求取消，当前步骤结束后可退出。

自动 ZIP 复用完整备份格式，保存在 `classroom-auto-<数据目录标识>/` 专属子目录；归属索引 `index.json` 原子保存文件名、大小与 SHA-256，新备份提交后才清理。仅删除索引内、路径与内容检查通过的旧自动备份。修改/占用/链接文件保留并提示；未知 ZIP、手动备份与恢复前快照不受影响。索引损坏时停止写入与清理；更换位置后原目录保留。清理失败不会把已完成备份标为失败。取消尚未完成的备份后 10 分钟再检查，也可手动立即重试；备份已经提交时只中止剩余清理并保留成功记录。

迁移或换机恢复后需确认位置并重新启用；自动备份默认位于数据目录的 `backups/`，建议另选受保护的备份介质。文件未加密。设置页显示最近成功、失败及重试时间；首页提示需处理的异常，最近成功时间仍是本地记录，不能替代恢复校验。

教师端“数据与设置”可保存完整 ZIP 备份，或进入独立的“校验 / 恢复备份”窗口。当前备份格式为 2：

- SQLite 在线备份得到一致性数据库；模型原件和样本随包保存。
- `backup_info.json` 记录格式版本、数据库版本、创建时间、数量概要，以及每个文件的大小和 SHA-256。
- 校验会核对完整文件清单、哈希、数据库完整性与外键、模型和样本内容。哈希用于发现损坏，不证明备份来自可信的人。
- 有效的旧 v2 模型在新备份中升级为内容签名 v3，原运行模型不修改。新训练直接生成 v3；复制、ZIP 解压造成的修改时间变化不会使 v3 失效。

恢复流程：

1. 关闭所有其他签到窗口，选择 ZIP 并校验。确认备份时间、学生数、课次数、签到数和模型状态。
2. 输入当前数据目录的管理密码。失败次数与锁定沿用原有规则；空目录无需口令。当前数据库确实无法读取时，须另外明确授权使用本机文件权限离线恢复。
3. 确认后重新校验同一份备份，进入维护状态。其他新版窗口存活时拒绝恢复，维护期间禁止新窗口打开该目录。旧版软件没有运行登记，必须人工关闭。
4. 原数据库及 WAL/SHM、样本和模型先完整移动至数据目录内的 `backups/pre_restore_<随机编号>/`，再安装经过校验的数据。
   原数据库可读时，同时生成同名 ZIP；如需撤回一次已完成的恢复，可在恢复窗口选择该 ZIP。原库损坏时保留原始文件快照，不宣称该快照可正常导入。
5. 安装后再次检查数据库和可用模型。替换失败自动回退；替换过程中进程中断，下次普通启动会先读取恢复日志并回退未提交的操作。
6. 完成后返回入口，使用**备份时的管理密码**登录。在“人脸授权”逐人重新核验告知、真实授权和期限，再登记确认；这是防止旧备份复活已撤回授权的保护，不代表授权记录遗失。人工点名、查询与导出可先使用，模型未就绪时再训练。最近成功恢复时间显示在“数据与设置”，恢复操作写入本地操作记录。恢复前快照含敏感数据，请保护并按保留策略清理。

旧格式 ZIP 缺少逐文件哈希，界面会明确提示；只有额外确认后才允许恢复。其数据库仍须通过结构、版本及完整性检查；恢复后不启用旧模型，须重新训练。新版备份若模型未就绪，同样恢复名单、考勤和样本，完成后需重新训练。

恢复只替换业务数据库、样本和模型。已有日志、备份与导出文件不被覆盖。ZIP 不含加密功能；样本、数据库、模型、口令摘要和恢复前快照均需按敏感文件保护。

## 人脸授权与资料清理

教师端“人脸授权”发布学校核定的版本化告知、登记本人/监护人明确同意的凭据引用及显式保存截止日，支持续期与撤回历史。截止日当天有效，次日零点停止人脸使用；首页与授权页提示受限人数和 14 日内到期人数。旧资料不自动补同意，人工点名保留。

受控清理先预览，再复核密码、填写原因并二次确认；保留有效授权者样本和考勤/授权历史，移除受限样本及受影响合并模型。中断可续办，未完成前暂停人脸、新授权和新备份；历史 ZIP、副本及恢复前快照需另外处理，不承诺不可恢复擦除。详见包内 `人脸授权与清理说明.md`，源码为 `docs/face-lifecycle.md`。

## 现场维护

教师登录后进入“现场维护”：独立检测摄像头，不采集、不识别、不签到；设备断线后等待释放，再手动重试。采集保留已存样本并补采剩余数量，学生端重试前重新检查课次与模型。检测、采集、签到共用设备锁，关闭维护窗口会等待释放。

可检查数据卷与其他保存位置的磁盘空间；低于 512 MiB 提醒，采集/训练/Excel/诊断保存至少需 100 MiB，备份另需预留约两倍源文件大小。教师端训练默认 180 秒、导出默认 120 秒，可分别调整 30–3600 秒；这是协作取消时限，不是强杀原生训练。

脱敏诊断 ZIP 仅包含环境版本、业务数量、容量、时限和白名单错误计数，不含原始日志、路径、数据库、模型、人脸或口令，不自动上传。数量和时间仍可能敏感，分享前请核对。完整操作说明见发行包内 `现场维护说明.md`，源码项目中为 `docs/maintenance.md`。

## 开发者构建

先创建 Python 3.11 环境并安装 `requirements-lock.txt`，再用 Windows PowerShell 5.1 或 PowerShell 7 执行。`tools/build_windows.ps1` 保存为 UTF-8 BOM / CRLF，以兼容 Windows PowerShell 5.1 对中文提示的解析：

```powershell
./tools/build_windows.ps1
# 或指定已安装运行依赖的 Python 3.11
./tools/build_windows.ps1 -Python '完整路径/python.exe'
```

脚本把固定版本的 PyInstaller 工具安装到项目内 `.build-tools/`，构建下载缓存放在 `build/pip-cache/`，避免依赖本机全局 pip 缓存的写入权限，不加入运行依赖；构建 `dist/ClassroomAttendance/`，执行发行包自检，确认输出不含 BAT，再生成 ZIP 和 SHA-256 文件。构建资源使用白名单，不复制数据库、样本、训练模型、备份或运行日志。

自动自检直接创建刚构建的 EXE 进程，使用独立临时数据目录，不经过 Windows Shell；180 秒未完成会结束本次自检并使构建失败。此方式用于非交互构建验证，不改变用户双击 EXE 时的发布者或安全区域判定。本机已实测 Shell 启动未签名 EXE 也可能出现“未知发布者”提示，不能把“发行包已移除 BAT”视为“EXE 已取得信任签名”。

自检覆盖嵌入式 Python、Tk、OpenCV face、Haar 资源、SQLite、图像读写、LBPH、人工点名、课程模板与周期生成、教师首页与课后核对、统计报表页面/五表 Excel/恢复后一致性、首次使用向导/中断续办/跳过与恢复状态、四时间/课前开放/学生展示/恢复一致性、旧 schema 3 备份恢复升级、自动备份/重启去重/迁移暂停、新窗口创建、完整备份恢复往返和冻结子进程启动。它使用临时数据与合成图片，不会打开真实摄像头。

自检还覆盖现场维护页、脱敏 ZIP、独立检测模拟断线/释放/手动重试，以及训练与导出时限的备份恢复；不打开真实设备，不等同于拔插与课堂连续签到验收。

自检还覆盖人脸授权页、授权与恢复后逐人复核、撤回和清理后保留考勤，并验证新 schema 5 与旧 schema 3 的恢复升级；所有资料和凭据均为合成测试数据。

## 交付验收边界

本机源码测试与发行包自检不能替代干净电脑验收。试点前仍需在未安装 Python、断网的 Windows 10/11 电脑上验证：首次启动、密码设置、真实摄像头、样本采集和签到；再在另一台电脑恢复备份，核对名单、记录和模型。还需通过实际下载的 ZIP 验证解压后直接启动 EXE 的安全提示情况；移除 BAT 不代表未签名 EXE 在其他机器上必然没有系统提示。当前不声称已完成这些现场验收，也不包含真实课堂准确率评测。

打包入口在导入 GUI 与相机模块之前调用 `multiprocessing.freeze_support()`；独立角色进程按 PyInstaller 的要求重置启动环境。参考 [PyInstaller 多进程与重启说明](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#multi-processing) 和 [资源路径说明](https://pyinstaller.org/en/stable/runtime-information.html)。
