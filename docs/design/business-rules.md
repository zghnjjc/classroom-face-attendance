# 业务规则 / Business Rules

> 本文档描述考勤系统的数据与业务规则，面向维护者与部署者。界面文案可能更简短，但以后端规则为准。
> 规则实现主要位于 `attendance_store.py`、`attendance_filters.py` 与 `camera_service.py`。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 课次（session） | 一次课程签到时段，包含课程、班级、开始/结束时间、迟到阈值、状态与应到名单快照 |
| 应到名单（roster） | 课次创建时保存的学生集合；每条成员记录包含当时姓名、班级与是否仍计入 |
| 签到记录（check-in） | 某学生在某课次的有效考勤结果；每个课次每个学生最多一条 |
| 人脸证据（face evidence） | 首次通过人脸识别产生签到时保存的不可变证据 |
| 操作记录（audit） | 管理操作、系统操作或人脸识别产生的本地审计事件 |
| 迟到阈值（late_at） | 从该时刻起签到记为迟到；由开始时间 + 迟到宽限计算 |
| 应到/已到 | 统计口径中的“人次”，同一学生不同课次分别计数 |

## 2. 课次状态

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| `draft` 待开启 | 已创建但未开始签到 | 开启签到、取消课次、查看/调整名单（按启用班级刷新）、查看详情 |
| `open` 签到中 | 正在接受人脸签到 | 结束签到、查看/调整名单、人工更正、导出 |
| `closed` 已结束 | 已手动结束或到时自动关闭 | 查看/调整名单、人工更正、导出；不能取消 |
| `cancelled` 已取消 | 未上课，填写原因取消 | 仅查询详情与名单；不能调整、不能签到、不计缺勤 |

状态由数据层通过事务更新；开启/结束/取消的非法转换会返回中文错误。

## 3. 创建课次

- 课程名称：必填，去除首尾空白后 1–80 字。
- 班级：必填，1–60 字；可使用“全部学生”表示全体启用学生。
- 开始/结束时间：本地时间，精确到分钟；要求 `开始 < 结束`，且单次签到时长不超过 **24 小时**（支持跨日）。
- 迟到宽限：整数 **0–180 分钟**。
- 迟到阈值：`late_at = min(开始时间 + 宽限, 结束时间)`。
- 应到名单：创建时按“启用学生 + 班级”生成快照，写入 `session_students`（保存当时的姓名与班级）。若指定名单，则必须是该班级内启用且存在的学生。
- 若班级没有启用学生，创建失败。
- 创建课次会写入操作记录（课程/班级/人数）。

## 4. 开启签到

数据层条件（全部满足）：

1. 课次状态为 `draft`；
2. 当前时间满足 `开始时间 <= 当前 < 结束时间`；
3. 当前没有其他 `open` 课次（过期未结束的会先被自动关闭）；
4. 应到名单中至少有一名仍计入（`included=1`）的成员。

管理端额外检查：

- 模型必须通过完整性校验（否则提示先训练/修复）；
- 若本课次有应到学生不在模型覆盖集合中，会弹窗确认，提示这些学生需要人工补签；确认后仍可开启。

开启成功写入操作记录。

## 5. 结束与取消

- **结束**：只能结束 `open` 课次；重复结束返回“无变化”。结束操作写入操作记录。
- **自动结束**：当 `结束时间 <= 当前时间` 时，程序在下一次课次/考勤查询中把 `open` 改为 `closed`，并写入系统操作记录（来源为系统）。若所有窗口都关闭，自动关闭不会在后台发生；下次查询会补做。
- **取消**：只能取消 `draft` 课次；必须填写 1–300 字原因；记录取消原因、取消时间与前后值。已取消课次不产生出勤/缺勤统计，只能查询。
- **过期未开启**：到结束时间仍未开启的 `draft` 课次不会自动变成缺勤；需要教师取消（填写原因）或保留为待开启。取消与“已结束”是两种不同语义。

## 6. 人脸签到接受条件

一次人脸签到只有在全部满足时才写入：

1. 课次状态为 `open`；
2. 签到时间满足 `开始时间 <= 当前 < 结束时间`（结束时刻不含）；
3. 学生在该课次应到名单中且 `included=1`；
4. 学生档案为启用状态；
5. 识别结果满足模型阈值与连续确认要求。

满足后：

- 状态判定：若签到时间 `>= late_at` 则 `late`，否则 `present`；
- 通过数据库唯一约束实现“同一学生同一课次最多一条”；
- 若该课次该学生还没有人脸证据，插入首次证据；若已有有效人工结果，则只补证据、不覆盖人工结果；
- 写入操作记录（人脸识别来源）；
- 同一学生同一天不同课次可以分别签到。

### 迟到边界

| 开始 | 宽限 | 结束 | late_at | 结果 |
| --- | --- | --- | --- | --- |
| 08:00 | 10 分钟 | 09:30 | 08:10 | 08:09:59 已签到；08:10:00 起迟到 |
| 08:00 | 0 | 09:30 | 08:00 | 从 08:00:00 起即迟到 |
| 09:00 | 180 分钟 | 09:40 | 09:40（取结束） | 结束前均不记迟到 |
| 跨日 23:30 | 10 分钟 | 次日 00:20 | 23:40 | 次日 00:19:59 前签到仍可记为迟到/已签到，00:20 起不再接受 |

结束时刻严格不含：`签到时间 < 结束时间` 才可能成功。

## 7. 考勤状态推导

界面与导出统一使用以下推导（详见 `attendance_store.ATTENDANCE_ROW_SQL`）：

| 条件 | 状态 |
| --- | --- |
| 成员 `included=0` | 已移出应到（不计入统计） |
| 课次 `draft` 且无签到 | 待开启（不参与缺勤） |
| 课次 `cancelled` | 已取消（不参与统计） |
| 有签到记录 | 按记录的 `present` / `late` / `leave` / `absent` |
| 课次 `open` 尚未结束、无签到 | 未签到（**不计缺勤**） |
| 课次 `open` 已过结束时间（已自动结束）或 `closed`、无签到 | 缺勤 |

统计只包含 `open` 与 `closed` 课次中的 `included=1` 成员；已移出、待开启与已取消不计入。

## 8. 人工更正

- **允许范围**：`open` 或 `closed` 课次；待开启/已取消课次不能更正。
- **前置条件**：学生必须在该课次名单中且 `included=1`。
- **必填原因**：1–300 字；状态必须是 `present` / `late` / `leave` / `absent` 之一。
- **实际到课时间语义**：
  - 若已有签到记录，默认保留原 `signed_at`；
  - 若要修改，可填写本地实际到课时间（不能带时区）或明确勾选“时间未确认”；
  - 状态为已签到/迟到且没有已有时间时，必须填写实际时间或明确选择“时间未确认”；
  - 选择“时间未确认”后时间显示为空，导出显示“时间未确认”，不能与具体时间同时提交；
  - 后续只改备注/状态且不提供时间时，不会凭空生成时间，也不会用更正时间替代。
- **记录方式**：人工更正后 `checkins.method` 记为 `manual`。
- **幂等**：若提交后的完整结果、原因与署名前一次完全相同，则不重复写操作记录。
- **证据保留**：人工更正不会修改 `face_evidence`；原始人脸签到时间与方式仍可在“原始证据/更正历史”和导出中查看。
- **事务**：更正结果与操作记录在同一事务内提交；任一步失败则回滚。
- **署名字段**：可填 0–80 字管理署名；未填写时来源为管理入口，填写后来源为“管理署名”。署名是自由文本，不是账号认证。

## 9. 原始人脸证据

- 首次通过人脸识别签到时，写入 `face_evidence`（签到时间、方式、记录时间、来源）。
- 数据库触发器禁止对 `face_evidence` 执行 UPDATE/DELETE；即使人工更正、名单移出或课次结束，证据保持原样。
- 旧版数据库升级时，只能把升级时仍存在的刷脸时间保存为证据（来源标记为 `migrated_current`）；已被旧版人工更正覆盖的原始时间无法反推，也不会伪造。
- 证据是本校/本机的管理记录，**不是**防篡改或司法级证据；拥有数据库文件权限的人仍可修改数据库或代码。

## 10. 名单快照与调整

- **快照**：课次创建时写入当时姓名与班级；之后学生档案改名/换班不会自动改变该课次名单，也不会改变历史展示。
- **待开启课次**：可按当前启用学生与课次班级刷新名单（新增/移出），不能与手工增补/移出同时执行。
- **签到中/已结束课次**：可按学号增补（要求学生存在且启用）或移出当前应到名单；必须填写原因。
- **移出**：只把 `included` 置 0，不删除签到与证据；统计不计入；可在“含移出人员的名单”中查看历史。
- **重新加入**：可通过增补恢复 `included=1`，已有签到/证据仍保留。
- **预览确认**：调整前必须先预览，预览结果带有基于课次状态、现有考勤与当前档案计算的令牌；确认时若数据已变化，令牌失效并要求重新预览。
- **无变化**：名单没有实际增减时不写操作记录。
- **已取消课次**：只能查询，不能调整名单。
- **停用学生**：停用只禁止后续人脸签到，并使该生默认不进入新课次；既有课次名单不变。停用不会使其他学生模型失效。

## 11. 考勤查询、统计与导出

- **时间范围**：当天、当周（周一至周日）、当月、当前学期。
- **学期默认划分**：2 月 1 日–8 月 31 日；9 月 1 日–次年 1 月 31 日。可按校历自定义起止日期（含结束当天），保存到数据库；支持恢复默认。
- **范围归属**：按课次**开始日期**归属；跨日课次归入开始当天。
- **范围边界**：查询起点包含、终点不含。
- **状态筛选**：全部 / 缺勤。
- **课次筛选**：全部课次或某个具体课次。
- **统计口径**：只统计 `open`/`closed` 课次；按“人次”计数；同一学生不同课次分别计数；进行中尚未签到的学生不计缺勤。
- **导出 Excel**：同时应用时间、状态与课次筛选；包含课程、课次编号、实际到课时间、原始人脸签到时间与到课时间说明；未知时间留空并在说明列写“时间未确认”；学号按文本写入；所有字符串单元格强制文本类型以降低公式注入风险。
- **单课次导出**：仅 `open`/`closed` 课次可导出；待开启与已取消不参与导出。

## 12. 操作记录（审计）

- 记录的动作包括：设置/修改/升级/重置管理密码、保存学生、启用/停用学生、批量导入、创建课次、开启/结束/取消课次、调整名单、人脸签到、保存首次人脸证据、人工更正、设置学期、删除/清空人脸数据等。
- 字段：时间、动作、课次、学生、说明、签名字段、来源类型、修改前 JSON、修改后 JSON。
- 来源类型：人脸识别、系统、管理入口、管理署名、旧版未知等。
- 查询界面最多展示最近 500 条；这**不是**自动删除，数据库仍保留全部记录。
- 审计是本地管理记录，不是防篡改账本，也不等同于司法证据。

## 13. 并发、事务与去重

- SQLite 使用 WAL 模式；读连接超时 2 秒、写连接超时 8 秒，业务繁忙时界面会提示重试。
- 关键写操作使用 `BEGIN IMMEDIATE`；签到、开启课次、更正等在同一事务内完成。
- 唯一约束：课次 + 学号（`checkins` / `face_evidence` / `session_students` 主键）保证去重与一致性。
- 采集与训练、相机使用、模型读写通过跨进程锁互斥；进程异常退出时由操作系统释放锁。
- 管理端与学生端可同时运行；数据库事务与刷新机制负责联动。

## 14. 识别与模型规则

- 检测：Haar 级联；要求画面中恰好一张人脸。
- 画质门槛：人脸区域至少 100 像素；平均亮度约 45–215；Laplacian 方差不低于 45。
- 预处理：灰度、缩放到 160×160、直方图均衡。
- 识别：LBPH；距离 **< 60** 视为候选身份；候选身份必须在本课次应到名单且启用。
- 连续确认：同一身份至少 **8 次**匹配且持续 **至少 1 秒**；身份变化/无人/多人/画质不足会重置。
- 复核：识别线程约每 **0.75 秒**检查课次状态、启用名单与模型版本；课次结束或模型变化时停止。
- 模型有效性：清单版本、学生集合、样本数、样本签名、模型 SHA-256 全部匹配才视为就绪；模型更新后正在进行的识别会停止并要求重新开始。
- 运行中再次签到同一学生不会覆盖第一次记录，只提示“本课次已有记录”。

## 15. 当前不支持的规则

- 不支持按学生单独设置迟到宽限或多次签到时间窗。
- 不支持自动按期限删除数据；保留期限需人工执行。
- 不支持多教师账号/角色、网络同步、跨设备课次、云端备份。
- 不支持活体检测、防照片/视频代刷；不得将识别结果作为唯一身份认证。
- 不支持已取消课次的恢复；如需恢复请重新创建课次并调整名单。
