# 业务规则 / Business Rules

> 本文档描述考勤系统的数据与业务规则，面向维护者与部署者。界面文案可能更简短，但以后端规则为准。
> 规则实现主要位于 `attendance_store.py`、`attendance_filters.py` 与 `camera_service.py`。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 课次（session） | 一次课程签到时段，包含课程、班级、开始/结束时间、迟到阈值、状态与应到名单快照 |
| 应到名单（roster） | 课次创建时保存的学生集合；每条成员记录包含当时姓名、班级与是否仍计入 |
| 签到记录（check-in） | 某学生在某课次的有效考勤结果；每个课次每个学生最多一条 |
| 人脸证据（face evidence） | 首次通过人脸识别产生签到时保存的不可变证据 |
| 操作记录（audit） | 管理操作、系统操作或人脸识别产生的本地审计事件 |
| 开放签到（opens_at） | 从该时刻起允许教师开启并接受签到 |
| 正式上课（starts_at） | 正式上课时间，决定课次日期与统计归属 |
| 迟到阈值（late_at） | 独立设置，从该时刻这一秒起签到记为迟到 |
| 关闭签到（ends_at） | 该时刻起不再接受签到 |
| 应到/已到 | 统计口径中的“人次”，同一学生不同课次分别计数 |

### 首次使用与续办

- 仅无管理密码、无学生/课次/操作历史的新数据目录自动建立 `first_use_v1` 进度；旧用户不自动建立。设置页“重新检查”对已完成及旧用户只复核现状，打开或关闭不写入未完成进度；明确点击“重新开始向导”并确认才重置步骤，密码、名单和考勤保留。未完成用户继续已有步骤。
- 首次使用状态先在读事务查询，仅确需创建、显式重置或迁移未完成进度时请求写锁，并在写事务中重新核对；启动入口已读取的进度传给登录页，直接打开教师入口仍自行检查。密码及锁定校验独立进行。
- 确认实际运行数据目录后设置密码，后续摄像头及名单页面只在登录后进入。续办复用现有管理密码、失败次数与锁定规则；进度不保存明文密码或图片。
- 摄像头需连续收到画面并由教师确认后才记为通过并保存编号，跳过不修改编号；测试只在内存中显示画面。重试前、离开步骤前及关闭前须等待设备释放，失败清除本次通过标记。
- 名单先验证整批并展示新增/更新及停用状态；确认令牌包含输入与相关旧档案，相关资料变化后拒绝提交。导入、操作记录及向导进度同事务提交，失败/取消回滚；已有停用状态不自动启用。
- 摄像头和名单均需通过、沿用或明确跳过才能完成。完成标记幂等，只代表设置流程已处理，不代表模型就绪或课堂识别已经验收。
- 已确认步骤随数据库备份恢复；未完成向导的数据目录变化后重置相机测试。完成后的旧用户不会因恢复而被强制重新引导。

## 2. 课次状态

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| `draft` 待开启 | 已创建但未开始签到 | 开启签到、取消课次、查看/调整名单（按启用班级刷新）、查看详情 |
| `open` 签到中 | 正在接受人脸签到 | 结束签到、查看/调整名单、人工更正、导出 |
| `closed` 已结束 | 已手动结束或到时自动关闭 | 查看/调整名单、人工更正、导出；不能取消 |
| `cancelled` 已取消 | 未上课，填写原因取消 | 仅查询详情与名单；不能调整、不能签到、不计缺勤 |

状态由数据层通过事务更新；开启/结束/取消的非法转换会返回中文错误。

## 3. 创建课次

- 课程名称：必填，去除首尾空白后 1–80 字。
- 班级：必填，1–60 字；可使用“全部学生”表示全体启用学生。
- 四时间点采用本地无时区时间，界面填写到分钟，底层保留秒；`opens_at <= starts_at <= late_at <= ends_at` 且 `starts_at < ends_at`，`ends_at - opens_at <= 24 小时`。
- 旧接口仍兼容整数 0–180 分钟宽限：未提供独立迟到起点时 `late_at = min(starts_at + 宽限, ends_at)`，未提供开放时间时 `opens_at = starts_at`。显式迟到起点不使用宽限。
- 创建时在操作记录保存四个时间点；到开放时间不自动开课。已结束/进行中课次没有直接改写时间的入口。
- 应到名单：创建时按“启用学生 + 班级”生成快照，写入 `session_students`（保存当时的姓名与班级）。若指定名单，则必须是该班级内启用且存在的学生。
- 若班级没有启用学生，创建失败。
- 创建课次会写入操作记录（课程/班级/人数）。

### 课程模板与周期生成

- 模板以带版本和修订号的 JSON 保存于现有 `metadata` 的 `course_template_v1:` 键；版本 1 沿用旧开始/宽限规则，四时间模板使用版本 2。模板名唯一，更新时校验修订号，已生成课次不随模板更新。
- 保存课程、班级、四个时分、前日开放/次日迟到/次日关闭选项、每周星期、周间隔和可选学号；不保存本次日期范围、跳过日期或署名。
- 正式上课日期范围含首尾，最多 366 天；周间隔 1–8，首日期所在周一为第 1 周起点。开放、迟到和关闭按所选日偏移展开，整个开放窗口不超过 24 小时。
- 按班级模式取生成时的启用学生；固定名单中每人须存在、启用并属于选定班级（跨班需选择全部学生）。已生成课次的姓名、班级、应到名单各自保存，不随档案或模板更新改变。
- 本机仅允许一个开放课次，周期生成对所有课程检查 `[开始, 结束)` 时段占用：未取消课次重叠视为冲突，相邻时段可用，已取消课次不占用。原有单次创建规则保持有效。
- 教师先预览全部日期、名单与冲突，可明确跳过停课或冲突日期。确认令牌绑定实际计划及名单快照；并发占用、所选成员资料或启用状态变化会要求重新预览。未涉及的人员或不重叠课次变化不阻止生成。
- 批量结果、名单快照、逐次创建记录及批量汇总在同一事务提交；失败、取消或超时回滚整批。生成的课次均为待开启，不会自动开课，也不自动产生缺勤；临时停课沿用取消入口。

## 4. 开启签到

数据层条件（全部满足）：

1. 课次状态为 `draft`；
2. 当前时间满足 `开放签到 <= 当前 < 关闭签到`，正式上课前也可开启；
3. 当前没有其他 `open` 课次（过期未结束的会先被自动关闭）；
4. 应到名单中至少有一名仍计入（`included=1`）的成员。

管理端“开启签到”（人脸入口）额外检查：

- 模型必须通过完整性校验（否则提示先训练/修复）；
- 若本课次有应到学生不在模型覆盖集合中，会弹窗确认，提示这些学生需要人工补签；确认后仍可开启。

开启成功写入操作记录。

“人工点名”窗口提供独立的“开启人工点名”按钮：教师必须填写 1–300 字原因，可选填未认证署名；不检查模型或相机，但必须满足上述全部数据层条件。操作记录标明人工开课及原因。课次仍使用相同的 `open` 状态，学生端在模型可用时仍可刷脸；没有另设第二个并发开放课次。

## 5. 结束与取消

- **结束**：只能结束 `open` 课次；重复结束返回“无变化”。结束操作写入操作记录。
- **自动结束**：当 `结束时间 <= 当前时间` 时，程序在下一次课次/考勤查询中把 `open` 改为 `closed`，并写入系统操作记录（来源为系统）。若所有窗口都关闭，自动关闭不会在后台发生；下次查询会补做。
- **取消**：只能取消 `draft` 课次；必须填写 1–300 字原因；记录取消原因、取消时间与前后值。已取消课次不产生出勤/缺勤统计，只能查询。
- **过期未开启**：到结束时间仍未开启的 `draft` 课次不会自动变成缺勤；需要教师取消（填写原因）或保留为待开启。取消与“已结束”是两种不同语义。

## 6. 人脸签到接受条件

一次人脸签到只有在全部满足时才写入：

1. 课次状态为 `open`；
2. 签到时间满足 `开放签到 <= 当前 < 关闭签到`（关闭时刻不含）；
3. 学生在该课次应到名单中且 `included=1`；
4. 学生档案为启用状态；
5. 识别结果满足模型阈值与连续确认要求。

满足后：

- 状态判定：若签到时间 `>= late_at` 则 `late`，否则 `present`；
- 通过数据库唯一约束实现“同一学生同一课次最多一条”；
- 若该课次该学生还没有人脸证据，插入首次证据；若已有有效人工结果，则只补证据、不覆盖人工结果；
- 写入操作记录（人脸识别来源）；
- 同一学生同一天不同课次可以分别签到。

### 迟到边界

| 开放签到 | 正式上课 | 迟到起点 | 关闭签到 | 结果 |
| --- | --- | --- | --- | --- |
| 07:40 | 08:00 | 08:05 | 09:30 | 07:40 起可签到；08:04:59 已签到，08:05:00 起迟到 |
| 07:40 | 08:00 | 08:00 | 09:30 | 课前可记已签到，从 08:00:00 起即迟到 |
| 08:50 | 09:00 | 09:40 | 09:40 | 所有接受的签到均不记迟到 |
| 23:00 | 23:30 | 次日 00:05 | 次日 00:20 | 次日 00:05:00 起迟到，00:20:00 起不再接受 |

结束时刻严格不含：`签到时间 < 结束时间` 才可能成功。

## 7. 考勤状态推导

界面与导出统一使用以下推导（详见 `attendance_store.ATTENDANCE_ROW_SQL`）：

| 条件 | 状态 |
| --- | --- |
| 成员 `included=0` | 已移出应到（不计入统计） |
| 课次 `draft` 且无签到 | 待开启（不参与缺勤） |
| 课次 `cancelled` | 已取消（不参与统计） |
| 有签到记录 | 按记录的 `present` / `late` / `leave` / `absent` |
| 课次 `open` 尚未结束、无签到 | 未签到（**不计缺勤**） |
| 课次 `open` 已过结束时间（已自动结束）或 `closed`、无签到 | 缺勤 |

统计只包含 `open` 与 `closed` 课次中的 `included=1` 成员；已移出、待开启与已取消不计入。

## 8. 人工更正

- **允许范围**：`open` 或 `closed` 课次；待开启/已取消课次不能更正。
- **前置条件**：学生必须在该课次名单中且 `included=1`。
- **必填原因**：1–300 字；状态必须是 `present` / `late` / `leave` / `absent` 之一。
- **实际到课时间语义**：
  - 若已有签到记录，默认保留原 `signed_at`；
  - 若要修改，可填写本地实际到课时间（不能带时区）或明确勾选“时间未确认”；
  - 状态为已签到/迟到且没有已有时间时，必须填写实际时间或明确选择“时间未确认”；
  - 选择“时间未确认”后时间显示为空，导出显示“时间未确认”，不能与具体时间同时提交；
  - 后续只改备注/状态且不提供时间时，不会凭空生成时间，也不会用更正时间替代。
- **记录方式**：人工更正后 `checkins.method` 记为 `manual`。
- **幂等**：若提交后的完整结果、原因与署名前一次完全相同，则不重复写操作记录。
- **证据保留**：人工更正不会修改 `face_evidence`；原始人脸签到时间与方式仍可在“原始证据/更正历史”和导出中查看。
- **事务**：更正结果与操作记录在同一事务内提交；任一步失败则回滚。
- **署名字段**：可填 0–80 字管理署名；未填写时来源为管理入口，填写后来源为“管理署名”。署名是自由文本，不是账号认证。

### 批量人工点名

- 入口位于课次页与考勤记录页；可以查询待开启课次的快照，但必须先开课，才能写入人工考勤。
- 教师明确多选人员，统一登记状态、原因及可选署名。默认逐人保留原时间；可明确填写统一本地时间，或选择时间未确认。既有备注不改动。
- 预览逐人展示原状态、新状态、原时间、新时间与是否需要重复登记。筛选切换清空选择，内容改变后必须重新预览。
- 确认令牌绑定课次、所选快照成员、当前结果、原始证据、最近更正及登记内容；同一事务内复核并提交，所选人员的并发变化会拒绝整批。未选人员正常刷脸不使预览失效。
- 整批结果、逐人的“人工更正”事件和“批量人工点名”汇总记录原子提交；失败、取消或超时回滚整批。重复相同内容重新预览后显示无需重复，不再增加事件。
- 已结束课次及仍在名单中的停用学生可人工核实；已移出人员、待开启或已取消课次不能直接登记。人工状态不被后续重复刷脸覆盖。

### 课后核对进度

- 只有 `closed` 课次可确认核对完成。确认前预览包含已移出成员的明细，统计只含应到成员；显示当前结果、实际到课时间、首次人脸时间、备注、缺勤与时间未确认人数。
- 核对说明选填 0–300 字，署名选填 0–80 字且未经认证。UI 须明确勾选核对确认，服务端复核预览快照；确认仅写核对标记和操作记录，不改考勤或证据。
- 标记以 `session_review_v1:<课次编号>` 保存于现有 metadata，并记录影响考勤的最后操作序号。人工更正、人脸结果/证据、名单调整或结束状态变化使旧标记失效；即使移出后重新加入并恢复相同值，也要再次核对。学生档案变化或其他课次操作不影响历史课次核对。
- 确认时同时复核完整结果与操作序号，预览后发生变化会拒绝；标记与操作记录同事务提交，失败回滚。相同结果、说明和署名重复确认不追加事件。
- 首页列出所有待核对的已结束课次总数，展示其中最近 30 个，按关闭时间倒序。统计日按正式上课日期；前日已开放或跨日当前课次单独展示。
- 标记是本地工作进度；没有独立账号或数据库文件防篡改能力。通过外部工具直接改库不属于程序操作流程。

## 9. 原始人脸证据

- 首次通过人脸识别签到时，写入 `face_evidence`（签到时间、方式、记录时间、来源）。
- 数据库触发器禁止对 `face_evidence` 执行 UPDATE/DELETE；即使人工更正、名单移出或课次结束，证据保持原样。
- 旧版数据库升级时，只能把升级时仍存在的刷脸时间保存为证据（来源标记为 `migrated_current`）；已被旧版人工更正覆盖的原始时间无法反推，也不会伪造。
- 证据是本校/本机的管理记录，**不是**防篡改或司法级证据；拥有数据库文件权限的人仍可修改数据库或代码。

## 10. 名单快照与调整

- **快照**：课次创建时写入当时姓名与班级；之后学生档案改名/换班不会自动改变该课次名单，也不会改变历史展示。
- **待开启课次**：可按当前启用学生与课次班级刷新名单（新增/移出），不能与手工增补/移出同时执行。
- **签到中/已结束课次**：可按学号增补（要求学生存在且启用）或移出当前应到名单；必须填写原因。
- **移出**：只把 `included` 置 0，不删除签到与证据；统计不计入；可在“含移出人员的名单”中查看历史。
- **重新加入**：可通过增补恢复 `included=1`，已有签到/证据仍保留。
- **预览确认**：调整前必须先预览，预览结果带有基于课次状态、现有考勤与当前档案计算的令牌；确认时若数据已变化，令牌失效并要求重新预览。
- **无变化**：名单没有实际增减时不写操作记录。
- **已取消课次**：只能查询，不能调整名单。
- **停用学生**：停用只禁止后续人脸签到，并使该生默认不进入新课次；既有课次名单不变。停用不会使其他学生模型失效。

## 11. 考勤查询、统计与导出

- **时间范围**：当天、当周（周一至周日）、当月、当前学期。
- **学期默认划分**：2 月 1 日–8 月 31 日；9 月 1 日–次年 1 月 31 日。可按校历自定义起止日期（含结束当天），保存到数据库；支持恢复默认。
- **范围归属**：按课次**正式上课日期**归属；前日开放与次日关闭不改变归属。
- **范围边界**：查询起点包含、终点不含。
- **状态筛选**：全部 / 缺勤。
- **课次筛选**：全部课次或某个具体课次。
- **考勤记录页即时汇总**：统计 `open`/`closed` 课次；按“人次”计数；同一学生不同课次分别计数；进行中尚未签到的学生不计缺勤。
- **导出 Excel**：同时应用时间、状态与课次筛选；包含课程、课次编号、实际到课时间、原始人脸签到时间与到课时间说明；未知时间留空并在说明列写“时间未确认”；学号按文本写入；所有字符串单元格强制文本类型以降低公式注入风险。
- **单课次导出**：仅 `open`/`closed` 课次可导出；待开启与已取消不参与导出。

### 11.1 学期统计报表

- **范围**：可用已保存学期或自定义日期，首尾日期均包含；按正式上课日期归属，跨日不重复。课程名称精确筛选；班级按学生的课次名单快照筛选。
- **课次资格**：只纳入 `closed` 或 `open` 且 `ends_at <= 生成时间` 的课次；不纳入进行中、待开启、取消课次，查询自身不修改课次状态。课次、名单及考勤在同一 SQLite 读事务中读取。
- **应到与已到**：每个已纳入课次的 `included=1` 名单成员各计一次应到；已签到和迟到计已到，请假与缺勤仍计应到。停用及档案转班不改变历史快照；人工更正与名单调整以生成时有效结果为准。
- **比率**：出勤率 =（已签到 + 迟到）/ 应到；准时率 = 已签到 / 应到。请假不从分母扣除。分母为 0 显示“—”；合计从总人次计算，不能平均逐行百分比。显示四舍五入至百分数小数点后两位，Excel 保留数值与百分比格式。
- **汇总分组**：学生按学号合并，姓名与班级显示所选范围最近一次快照；课程按课程名称与课次班级合并，同名同班合并。未进入所选课次名单的学生不凭当前学生档案补零。
- **矩阵**：列按正式上课时间、课次编号排序，每个课次独立一列；“—”仅表示不在该次应到名单中，不能解释为缺勤。单元格明细保留当次姓名/班级快照和四个时间点。
- **时间与证据**：人工登记时间未确认仍按有效状态计数，单独汇总未确认数量；首次人脸证据只在明细呈现，不覆盖人工更正。
- **导出**：页面生成后保留一致快照，导出不重新查询；修改筛选后必须重新生成。一个文件包含学生汇总、课程汇总、矩阵、明细及统计口径，标注日期、课程、历史班级与生成时间。取消或失败不覆盖旧目标文件。考勤/名单变化后需手动重新生成。

### 11.2 数据版本兼容

- 当前为 schema 5：schema 4 在原 `sessions` 添加 `opens_at`；schema 3 升级时回填 `opens_at=starts_at`，原开始时间继续作为正式上课，原迟到与关闭值不变。schema 5 新增告知、授权/撤回和清理任务表，不推定旧资料已同意。
- 迁移与版本更新同事务，失败回滚；不修改签到、首次人脸证据、密码或模板。核对指纹对 `opens_at=starts_at` 的旧课次保持兼容，已有有效核对不会仅因补列而失效。
- 备份只读验证 schema 3/4/5、清单与实际版本对应关系；schema 4/5 必须有开放字段且四时间顺序有效，schema 5 还需生命周期结构、有效记录且无待续办清理。旧备份恢复后首次打开时迁移；所有恢复后的旧授权需逐人核验后新登记，不让较早备份复活撤回，人工点名保留。
- 不支持用旧版操作升级后的数据目录；回退须使用升级前备份。未知或更高版本拒绝迁移和恢复。

## 12. 操作记录（审计）

- 记录的动作包括：设置/修改/升级/重置管理密码、保存学生、启用/停用学生、批量导入、创建课次、开启/结束/取消课次、调整名单、人脸签到、保存首次人脸证据、人工更正、设置学期、删除/清空人脸数据等。
- 字段：时间、动作、课次、学生、说明、签名字段、来源类型、修改前 JSON、修改后 JSON。
- 来源类型：人脸识别、系统、管理入口、管理署名、旧版未知等。
- 查询界面最多展示最近 500 条；这**不是**自动删除，数据库仍保留全部记录。
- 审计是本地管理记录，不是防篡改账本，也不等同于司法证据。

## 13. 并发、事务与去重

- SQLite 使用 WAL 模式；读连接超时 2 秒、写连接超时 8 秒，业务繁忙时界面会提示重试。
- 关键写操作使用 `BEGIN IMMEDIATE`；签到、开启课次、更正等在同一事务内完成。
- 唯一约束：课次 + 学号（`checkins` / `face_evidence` / `session_students` 主键）保证去重与一致性。
- 采集与训练、相机使用、模型读写通过跨进程锁互斥；进程异常退出时由操作系统释放锁。
- 管理端与学生端可同时运行；数据库事务与刷新机制负责联动。

## 14. 识别与模型规则

- 检测：Haar 级联；要求画面中恰好一张人脸。
- 画质门槛：人脸区域至少 100 像素；平均亮度约 45–215；Laplacian 方差不低于 45。
- 预处理：灰度、缩放到 160×160、直方图均衡。
- 识别：LBPH；距离 **< 60** 视为候选身份；候选身份必须在本课次应到名单且启用。
- 连续确认：同一身份至少 **8 次**匹配且持续 **至少 1 秒**；身份变化/无人/多人/画质不足会重置。
- 复核：识别线程约每 **0.75 秒**检查课次状态、启用名单与模型版本；课次结束或模型变化时停止。
- 模型有效性：清单版本、学生集合、样本数、样本签名、模型 SHA-256 全部匹配才视为就绪；模型更新后正在进行的识别会停止并要求重新开始。
- 运行中再次签到同一学生不会覆盖第一次记录，只提示“本课次已有记录”。

## 15. 当前不支持的规则

- 不支持按学生单独设置迟到宽限或多次签到时间窗。
- 保存截止日由教师核验后显式填写，截止当天有效；14 日内提醒，次日零点停止人脸使用。未登记/撤回/旧告知/恢复待复核也受限；采集每次保存、应用训练和签到事务校验，含受限身份的合并模型整体暂停。不会静默删除资料。
- 受控清理须预览、密码、原因及二次确认，保护有效授权原始样本、名单、考勤和授权历史；清单变化拒绝旧预览。清理意图先落库，逐文件哈希核对后暂存并删除，失败可续办，期间暂停人脸、新授权与新备份。历史副本不自动追溯清理，文件删除不代表不可恢复擦除。
- 不支持多教师账号/角色、网络同步、跨设备课次、云端备份。
- 不支持活体检测、防照片/视频代刷；不得将识别结果作为唯一身份认证。
- 不支持已取消课次的恢复；如需恢复请重新创建课次并调整名单。
