# 课堂签到 · Classroom Face Attendance

> 本地离线的小班课堂人脸签到与考勤桌面工具（Windows · Python 3.11 · OpenCV LBPH · Tkinter · SQLite）。
>
> An offline, Windows-first classroom face check-in and attendance desktop tool.

> [!WARNING]
> **隐私提示**：人脸图像与人脸模板属于敏感个人信息。请只采集本人（或未成年人监护人）明确知情同意的样本，并遵守所在学校与当地法律的要求。
> 不要把真实姓名、学号、人脸图片、样本、数据库、模型、备份或含真实数据的日志提交到任何公开仓库、Issue、PR 或 Release。

本项目是本地单机工具：仓库本身不包含任何真实学生数据、人脸样本、训练模型、考勤数据库或备份。
学生端刷脸签到；教师端维护名单、采集样本、训练模型、创建课次、核对考勤并导出 Excel。
全部数据保存在运行本机的磁盘上，程序不发起网络请求。

## 功能特性

- **学生端刷脸签到**：当前课次自动出现，点击开始后相机预览直接显示；一次一人，可连续为多位学生签到。
- **教师端管理**：学生名单增删改、停用/启用、CSV/XLSX 批量导入、下载模板。
- **人脸采集与训练**：每位学生默认采集 20 张通过画质检查的样本，训练 Haar + LBPH 模型并记录模型版本与样本签名。
- **课次与名单**：创建课次、保存应到名单快照、开启/结束/取消课次；支持待开启课次按班级刷新名单，签到中/已结束课次按学号增补或移出（需原因与预览确认）。
- **考勤规则与更正**：自动区分已签到、迟到、请假、缺勤、已取消、已移出；人工更正需填写原因，保留原始到课时间与更正历史。
- **查询与导出**：按当天、当周、当月、当前学期筛选，按“全部/缺勤”过滤，Excel 导出沿用筛选条件。
- **原始证据**：首次人脸签到证据独立保存，不可更新或删除；人工更正不覆盖该证据。
- **本地备份**：一键生成包含数据库、模型与样本的 ZIP 完整备份。
- **数据安全习惯**：SQL 全部参数化；Excel 导出强制文本写入以降低公式注入风险；管理密码使用 PBKDF2-HMAC-SHA256；运行日志脱敏。
- **离线运行**：代码中无网络访问；不依赖云服务、账号体系或外部接口。

## 快速开始

### 1. 获取代码并创建虚拟环境

在仓库根目录打开 PowerShell：

```powershell
py -3.11 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-lock.txt
```

若系统没有 `py` 启动器，可将 `py -3.11` 换成指向 Python 3.11 的 `python`。

### 2. 启动程序

```powershell
./.venv/Scripts/python.exe GUI.py
```

或双击仓库根目录的 `start.bat`（入口选择页），再选择“学生签到”或“教师管理”；
也可以直接双击 `student.bat` 或 `admin.bat`。

> `.bat` 使用 `pythonw.exe` 启动，没有控制台窗口。如果启动失败或需要看到错误输出，
> 请在终端运行 `./.venv/Scripts/python.exe GUI.py`。

### 3. 首次使用

- 首次进入教师管理端时，需要**自行设置管理密码**（8–128 个字符，没有默认密码）。
- 首次启动会自动创建空数据库；初始化种子文件 `initial_data.json` 为空模板，不会导入示例学生。
- 学生端在老师开启课次后才会允许开始识别；模型尚未训练时，学生端会提示联系老师。
- 依赖分工：日常安装/CI 使用固定版本的 `requirements-lock.txt`；`requirements.txt` 只描述版本范围，供升级依赖时参考。
- 不要同时安装多个共用 `cv2` 命名空间的 OpenCV 发行包；本项目需要 `opencv-contrib-python`（含 face 模块）。

## 使用流程

### 教师端（6 步）

1. **维护名单**：在“学生与人脸”新增学生（学号 1–24 位数字，保留前导零；姓名、班级可选填班级默认“未分班”），或导入首行含“学号、姓名”的 `.xlsx` / `.csv`；整批导入失败时不会写入部分数据。
2. **采集人脸**：选择已保存且启用的学生，点击“采集人脸”，保持画面中一人并按提示缓慢转头、改变表情；默认采集 20 张，提前结束会保留已保存样本。
3. **更新模型**：点击“更新识别模型”。新模型只纳入启用学生；页面会提示已覆盖与尚未训练的学生。样本变动后需要重新训练。
4. **创建课次**：在“课次管理”填写课程、班级、签到起止时间与迟到宽限（0–180 分钟），单次签到时长不超过 24 小时；创建时保存应到名单快照。
5. **开启签到**：选中课次后点击“开启签到”。需要可用模型，且当前时间必须处于课次时段内；同一时刻只允许一个开放课次。部分应到学生尚无模型时会提示老师确认，这些学生需要人工补签。
6. **结束与核对**：签到中的课次可手动结束或到时自动结束；在“考勤记录”筛选、核对、人工更正并导出 Excel。未开启的课次超时不算缺勤，未上课请填写原因并取消课次。

### 学生端（5 步）

1. 打开学生端，等待老师开启课次。
2. 点击“开始识别”，相机预览显示在页面内。
3. 每次一人正对摄像头，保持清晰稳定；通过连续身份确认后显示本人签到结果与时间。
4. 相机可持续为多位学生签到，不需要每位学生重新点击；重复签到不会覆盖第一次记录。
5. 课次结束时相机会自动停止，也可以手动停止。

学生端不展示全班名单；结果中的姓名只显示首字加星号，学号只显示末尾少量字符。请假、缺勤等人工结果不会被后续重复刷脸直接覆盖。

## 考勤规则（摘要）

- **签到时段**：只有在课次开始时间至结束时间之间（结束时刻不含）且课次状态为“签到中”时才接受人脸签到。
- **迟到**：从“开始时间 + 迟到宽限”这一秒起记为迟到；宽限为 0 时从开始时间起计迟到；宽限覆盖整个课次时结束前均不记迟到。迟到阈值与结束时间取较早者。
- **缺勤**：已结束课次的未签到应到学生计缺勤；签到中的未签到显示“未签到”，不计为缺勤；待开启、已取消、已移出名单的人员不参与统计。
- **取消与结束**：只有待开启课次可取消（需填写原因），只有签到中的课次可结束；已结束课次不能取消，未开启课次超时也不产生缺勤。
- **唯一记录**：同一学生在同一课次最多一条有效签到记录；同一天不同课次可分别签到。数据库唯一约束与事务负责去重。
- **更正**：只有签到中或已结束课次可以人工更正；必须填写 1–300 字原因。实际到课时间默认保留，补签时须填写时间或明确勾选“时间未确认”。相同更正重复提交不会重复写事件。
- **证据**：首次人脸签到证据独立保存，更正状态或到课时间不会覆盖原始证据。
- **名单快照与调整**：课次创建时保存成员姓名与班级；后续档案修改不会自动改变该课次名单。待开启课次可按当前启用班级刷新新增/移出；签到中与已结束课次可按学号增补或移出，需填写原因并先预览确认；移出后原有签到与证据仍保留。
- **操作署名**：教师署名是选填的管理操作署名，未经独立账号认证；未署名时记录为管理入口操作，不能据此认定真实身份。

详细规则见 [docs/design/business-rules.md](docs/design/business-rules.md)。

## 相机与模型

- 人脸检测使用 OpenCV Haar 级联，身份识别使用 LBPH；输入为灰度图，训练前缩放到 `160×160` 并做直方图均衡。
- 默认摄像头编号为 0，可在管理端“数据与设置”修改（0–9）；采集与签到共用跨进程相机锁，两个窗口不能同时占用相机。
- 识别距离阈值为 **小于 60**；同一身份需要连续 **至少 8 次**匹配且持续 **至少 1 秒**才算确认。
- 识别线程约每 **0.75 秒**复核课次、启用名单与模型版本；检测到课次结束或模型失效会停止。
- 采集/识别有画质门槛：人脸区域至少 100 像素，亮度约 45–215，清晰度（Laplacian 方差）不低于 45。
- 模型与样本签名（文件名、大小、修改时间）及模型 SHA-256 一起保存；样本变化、模型损坏或版本不符时提示重新训练。停用学生不会使其他学生的模型失效。
- **没有经过验证的活体检测**：二维摄像头 + LBPH 无法可靠区分真人、照片或视频，**不得宣传“防代刷”**。连续确认与画质检查不等于活体检测。
- 识别准确率受光线、角度、摄像头质量、样本数量影响，**尚未经过充分的现场验证**；正式使用前应在本班环境试运行，并保留人工核对与补签渠道。

## 数据与隐私

### 运行数据文件

| 路径（默认在项目根目录） | 内容 |
| --- | --- |
| `attendance.db`（含 `-wal`/`-shm`） | 学生姓名、学号、班级、课次与名单快照、签到、原始人脸证据、操作记录、管理密码摘要、学期与摄像头设置 |
| `dataset/` | 人脸样本 JPEG 裁剪图 |
| `face_model.yml` | LBPH 人脸模型 |
| `model_manifest.json` | 模型版本、学生集合、样本数、样本签名、模型哈希 |
| `logs/classroom.log`（及轮转文件） | 运行诊断日志，已脱敏，不含姓名、学号、口令、异常值或图像 |
| 用户选择的 `backups/*.zip` 或备份位置 | 数据库、模型、样本与备份信息 |
| 用户导出的 `.xlsx` | 姓名、学号、班级、考勤状态、时间与备注 |
| `.camera.lock`、`.samples.lock` | 运行期资源锁文件，程序退出后失效 |
| `initial_data.json` | 空初始化种子（仓库内只保留空模板） |

> 可通过环境变量 `CLASSROOM_DATA_DIR` 将运行数据目录指向其他位置；请确保该目录同样受访问控制与备份保护。

### 隐私要点

- **本地存储、无网络**：代码中没有任何网络请求、上传、遥测或云同步；数据只保存在运行本机。
- **敏感个人信息**：人脸图像与人脸模板属于生物识别信息，姓名 + 学号 + 考勤结果可识别到具体学生。部署者（学校/教师）应在采集前告知用途、范围、保存期限，并取得学生（未成年人需监护人）的明确同意；在适用法律要求时履行个人信息保护义务。
- **访问控制**：管理密码只保护本机管理界面，**不是操作系统权限隔离**。能访问项目文件或数据库的人仍可修改程序或数据；请使用受保护的 Windows 账户，并考虑启用 BitLocker 等磁盘加密。
- **备份保护**：完整备份 ZIP 包含数据库、人脸样本、模型与管理密码摘要，且默认未加密。请保存到受保护位置并加密（如加密压缩包/加密磁盘），不要上传网盘、聊天工具或代码仓库。
- **日志**：日志只保留错误类型和文件、行号、函数调用链，去掉异常值、源代码与局部变量；日志仍属运行数据，删除数据时一并清理。
- **导出表格**：导出的 Excel 含姓名、学号与考勤信息，请按敏感文件管理。

### 删除与重置

- **删除某个学生的人脸资料**：在管理端“数据与设置”选择“删除选中学生人脸”，需复核管理密码并二次确认；会删除样本并重建模型，**保留**名单与考勤时间证据。
- **清空全部训练数据**：在“数据与设置”选择“清空全部训练数据”，同样需复核管理密码；之后须重新采集并训练才能刷脸。
- **忘记管理密码**：关闭全部签到程序后，在仓库根目录执行：

  ```powershell
  ./.venv/Scripts/python.exe reset_admin.py --data-dir . --confirm-reset
  ```

  脚本会先把当前数据库备份为 `password_reset_<时间戳>.db`，再删除管理密码摘要；下次进入教师端需重新设置密码。
  备份文件含敏感数据，请妥善加密保存或按保留策略删除。
- **彻底删除全部数据**：关闭全部程序后删除 `attendance.db`（含 `-wal`、`-shm`）、`dataset/`、`face_model.yml`、`model_manifest.json`、`logs/`、`backups/` 以及导出的 `.xlsx` 与重置备份。
  注意：如果删除了数据库但保留了模型或样本，启动检查会提示缺少数据库；请把运行数据一起删除或一起保留。需要保留考勤结果时，先导出并加密保存。
- **原始人脸证据**：数据库触发器禁止单条更新或删除首次人脸证据；如需行使删除权，应通过管理端删除人脸样本并评估是否整体删除数据库。

更多说明见 [docs/data-and-privacy.md](docs/data-and-privacy.md)。本文档不构成法律意见；正式部署前请咨询学校或专业法律人员。

## 已知限制

- **无活体检测**，不能阻止照片/视频/屏幕翻拍代刷；识别结果只能作为辅助记录。
- **准确率未充分验证**：LBPH 对光线、角度、遮挡和摄像头差异敏感；未做大规模、多人、长时间现场验证。
- **单机单摄像头**：同一时刻只允许一个开放课次；没有多机位、多教室同步或网络集中管理。
- **无账号体系**：教师端只有一个共享管理密码，没有多教师账号、角色权限或独立审计身份；教师署名是选填文本，不构成实名认证。
- **本地文件可信边界**：管理密码不防御拥有本机文件权限的人；数据库、样本、模型、备份默认未加密；操作记录是本地管理记录，不是司法级防篡改证据。
- **平台限定**：仅在 Windows 10/11 + Python 3.11 验证；Linux/macOS、其他 Python 版本未验证。
- **无安装包**：需要用户自行准备 Python 3.11 环境；未提供 PyInstaller 便携包。
- **后台任务默认 30 秒超时**：训练、备份与导出共用默认超时；学生/样本较多、使用网络盘或磁盘较慢时可能提示“操作超时”（不会留下半成品，但需要重试或分批操作）。
- **窗口尺寸**：教师端最小窗口较高（约 1080×840），在 1366×768 等小屏上可能显示不完整。
- **到时自动关闭**：由运行中的程序通过查询触发（约每 1–3 秒刷新）；所有窗口都关闭时不会在后台关闭课次，但下次查询会补做关闭。
- **无云端能力**：不支持移动端、Web、在线选课、消息推送或跨设备同步。
- **未提供示例截图/演示 GIF**：仓库只预留 `docs/images/`；制作演示素材必须使用虚构数据并对人脸打码。

## 测试与 CI

当前仓库测试套件共 **136 项** unittest，覆盖 9 个测试文件。测试使用临时数据库、合成图片与模拟相机，不依赖真实人脸、真实摄像头或生产数据库。

在仓库根目录执行：

```powershell
./.venv/Scripts/python.exe -m unittest discover -s tests -v
./.venv/Scripts/python.exe -m pip check
```

注意事项：

- 测试必须在**仓库根目录**运行（测试按项目根目录导入模块）。
- 大多数 GUI 测试会创建真实 Tk 根窗口，因此需要**桌面图形会话**；无头环境需使用 Windows runner 或 Linux + Xvfb。
- 测试会写入临时目录，不需要也不应使用正式 `attendance.db`。
- CI 工作流位于 `.github/workflows/tests.yml`：Windows + Python 3.11 + 依赖缓存 + `pip check` + Tk 冒烟 + 全量 unittest，权限为 `contents: read`。
- README 中的 CI 徽章状态由首次推送后的 GitHub Actions 运行结果决定；运行记录见仓库 Actions 页面。

测试说明与覆盖范围见 [docs/testing.md](docs/testing.md)。

## FAQ

**Q：提示“摄像头正在使用”或相机打不开？**
A：同一台电脑上采集与签到共用相机锁。先停止学生端识别，再进行采集/训练；关闭其他占用摄像头的程序；确认摄像头编号（0–9）；USB 摄像头可尝试重新插拔，必要时重启程序。

**Q：提示“请先训练模型”“样本已更新”或“模型信息损坏”？**
A：完成（或补采）样本后点击“更新识别模型”。如果手动修改/删除了 `dataset/`，或从别处复制了模型与样本，二者签名不一致，需要重新训练。停用学生不需要重新训练。

**Q：忘记管理密码怎么办？**
A：关闭全部程序，执行 `reset_admin.py --data-dir . --confirm-reset`（见“删除与重置”）。脚本会先备份数据库，再清除密码摘要；下次进入管理端重新设置密码。

**Q：学生停用后有什么影响？**
A：停用只禁止后续人脸签到，并使该生默认不进入新课次名单；既有课次的应到名单不变。停用不会让其他学生的模型失效；重新启用但尚无模型覆盖的学生会提示需要训练或人工补签。

**Q：如何清空所有数据或重新开始？**
A：局部删除用管理端“删除选中学生人脸”/“清空全部训练数据”；彻底清空按“删除与重置”删除数据库、样本、模型、日志、备份和导出文件。删除后重新启动会得到空项目，重新设置密码并导入名单。

**Q：画面里有多个人会怎样？**
A：识别要求画面中恰好一张人脸；多人、无人、身份变化或画质不足时不会签到，只提示调整。请一次一人正对摄像头。

**Q：为什么学生端看不到课次？**
A：需要老师创建课次并在时段内点击“开启签到”，且同一时刻只能有一个开放课次；模型需先训练且未失效。学生端会每 2 秒刷新当前课次。

**Q：能不能把程序放到另一台电脑？**
A：可以，但只复制代码/依赖环境；数据需要按备份流程迁移，并重新训练模型以匹配新机器上的样本。备份 ZIP 与数据库包含敏感数据，迁移与保存都需加密。

**Q：识别结果可以直接作为考勤依据吗？**
A：不建议。当前实现没有活体检测，准确率也未经充分验证；请保留教师核对、人工更正与补签流程。
